## Original issue body

## Problem

Superscale is currently licensed and presented as MIT source code in repository documentation, CLI help text, Homebrew release metadata, and the current formula. The project is about to expand in scope, so the source-code licence should move to Apache-2.0 before the next feature set lands. The change must preserve the existing split licensing model for model weights and must not imply that third-party model artefacts have been relicensed.

The intended licence and trademark position is:

- Superscale source code is licensed under Apache-2.0.
- Bundled Real-ESRGAN/CoreML model weights remain separately licensed under BSD-3-Clause.
- Optional GFPGAN weights are not redistributed by Superscale and remain available only as explicit user-initiated downloads governed by upstream non-commercial terms.
- Superscale and the Superscale logo are declared as trademarks, with permitted descriptive use and prohibited confusing product-identity use documented for forks.

The licence change touches user-visible code paths, not just documentation. The CLI help text currently reports MIT, the release script generates a Homebrew formula with `license "MIT"`, and the checked-in formula currently reports MIT. The GUI also has licence surfaces for optional GFPGAN download and app metadata; these must continue to present the existing non-commercial model terms without wording or behaviour changes, except where an app surface reports the Superscale source-code licence as MIT and must instead report Apache-2.0. The GUI About modal should present the Superscale source-code licence under the Superscale app identity and above the separate model licence summaries.

The README should present the Superscale logo from `docs/sslogo.svg` where appropriate. If the SVG is unavailable or unsuitable, `docs/sslogo.png` may be used instead.

The About modal must identify Apache-2.0 for the Superscale source-code licence, and the app must continue to present the NVIDIA and CC BY-NC-SA licence screens before download; this behaviour must remain intact after the broader licence update.

`UT-69.1` remains a user test because README logo placement and trademark policy posture require human visual and policy judgement.

## Solution Design

### Affected surfaces

Update all current source-code licence surfaces from MIT to Apache-2.0:

- `LICENSE`
- `README.md`
- `Sources/Superscale/HelpText.swift`
- `scripts/release.sh`
- `Formula/superscale.rb`
- any GUI/app metadata that displays the project source-code licence, if present
- any package/distribution metadata that displays the project source-code licence

Preserve model-weight licensing and acceptance surfaces:

- `THIRD_PARTY_LICENSES`
- `docs/model-licensing.md`
- `Sources/Superscale/SuperscaleCommand.swift` GFPGAN CLI download notice and interactive acceptance prompt
- `SuperscaleApp/SuperscaleApp/FaceModelDownloadView.swift` GUI review/acceptance flow
- `SuperscaleApp/SuperscaleApp/Resources/LICENCE_NVIDIA.txt`
- `SuperscaleApp/SuperscaleApp/Resources/LICENCE_CC_BY_NC_SA.txt`
- `SuperscaleApp/SuperscaleApp/ModelPicker.swift` and `AboutView.swift` licence summaries

Add new attribution and trademark documentation:

- Add root `NOTICE` for Apache-2.0 notice handling.
- Add `docs/trademark.md` or `docs/TRADEMARKS.md` declaring Superscale and the Superscale logo as trademarks of Taḋg Paul.
- Use `docs/sslogo.svg` in README with accessible alternate text. Use `docs/sslogo.png` only if the SVG is unavailable or unsuitable.

### Licence model

Use this split model throughout repository and product-facing text:

- Superscale source code: Apache-2.0.
- Bundled Real-ESRGAN converted model weights: BSD-3-Clause third-party artefacts.
- Optional GFPGAN weights: not redistributed by Superscale; downloaded only after explicit user review/acceptance of upstream non-commercial terms.

Avoid wording that says the whole release artefact is Apache-2.0 when model weights are present. Preferred wording:

> Superscale source code is licensed under Apache-2.0. Bundled model weights are separately licensed; see `THIRD_PARTY_LICENSES` and `docs/model-licensing.md`.

### Non-commercial licence acceptance auditability

The existing acceptance model appears to be transactional rather than persisted: the CLI requires an interactive terminal, displays a licence notice, and asks for `[y/N]`; the GUI displays the NVIDIA and CC BY-NC-SA licence screens and proceeds only after the user clicks `I Agree` through both screens. Documentation should state this explicitly.

If implementation discovers a persisted acceptance record already exists, document where it is stored and how it relates to the installed GFPGAN model. If no persisted acceptance record exists, do not add one in this issue unless explicitly approved; document that the model is downloaded only through interactive acceptance and that the installation itself is the local result of that acceptance.

### Trademark model

The trademark document should:

- Declare Superscale and the Superscale logo as trademarks of Taḋg Paul.
- Permit truthful descriptive references such as "based on Superscale", "compatible with Superscale", or "forked from Superscale".
- Prohibit confusing product-identity use, including naming a fork "Superscale", using the Superscale logo as a fork's own app icon/product mark, implying endorsement, or presenting modified builds as the official Superscale app.
- Clarify that Apache-2.0 does not grant trademark rights beyond reasonable origin description and notice reproduction.

### Tests

Extend `Tests/SuperscaleTests/LicensingTests.swift` for repository/documentation/distribution metadata checks where the tested artefact is itself user-visible or release-visible.

Extend CLI tests only where they exercise actual CLI output, not source-code strings. `superscale --help` is the appropriate entry point for the CLI licence text.

Use an app/UI test or existing GUI test harness for the GFPGAN GUI licence flow only if the current UI test setup can cover the review/acceptance screens without introducing brittle visual assertions. Otherwise, keep this covered by direct view/resource tests plus the UT for human review.

### Documentation standards

Sanitize edited Markdown files according to documentation standards before committing. Keep documentation voice impersonal and preserve historical licensing notes where relevant instead of silently deleting history.

### Anti-patterns to avoid

- Do not relicense Real-ESRGAN model weights as Apache-2.0.
- Do not imply GFPGAN weights are bundled, redistributable, or commercially licensed.
- Do not rely on Apache-2.0 alone for trademark control.
- Do not add persisted acceptance tracking for GFPGAN unless it is explicitly approved as a scope change.
- Do not change app functionality. The CLI and GUI behaviour must remain the same except for source-code licence text changing from MIT to Apache-2.0.
- Do not change app-facing wording except where the current MIT source-code licence wording must become Apache-2.0. GFPGAN, Real-ESRGAN, help text, tooltip, dialogue, and acceptance wording should otherwise remain unchanged.
- Do not test source-code strings when a user-facing command output path exists.
