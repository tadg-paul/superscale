## Original issue body

Delivery master for the Superscale v2 MVP. This issue coordinates and accepts the delivery tree; it does not duplicate child specifications.

The design of record is [`docs/IMPLEMENTATION_GUIDE_v2.md`](../blob/master/docs/IMPLEMENTATION_GUIDE_v2.md). Wire-level provider detail is in [`docs/FAL_REQUEST_REFERENCE.md`](../blob/master/docs/FAL_REQUEST_REFERENCE.md).

## Confirmed goal

Deliver a single-workspace Superscale in which a user imports an image, browses the 86 built-in filters, applies one through `xai/grok-imagine-image/edit`, locks the iterations worth keeping, and receives native local upscaling.

The MVP exists to put a coherent working experience in front of human judgement, not to be feature-complete.

- Every child issue is drafted, designed, audited, implemented, verified and closed under the MODE DELIVER lifecycle.
- Slice 0 lands first, in its own commit, before any other work.
- Asset-graph invariants I1 to I7 are enforced and unit-tested without network access or Core ML.
- Defects D1 to D8 are closed, including the one-pixel black border, with a regression test that samples the outermost row and column.
- All four Gate 2 hard blocks are satisfied, including a documentation review recorded as review evidence and not established by any test that inspects documentation text.
- `make test` passes with zero errors and no new warnings. The SSIM quality gate is required on slice 3, which modifies the tested v1 core.
- Every rolled-up user test has an explicit human result.

Added by the `CONFIRM DELIVER` of 2026-08-25, both reported from use and both failing a user test:

- **The progress overlay blurs the picture.** `ProgressOverlay.swift:19` frames the overlay at `maxWidth: .infinity, maxHeight: .infinity`, and `MainView.swift:103` backs that full-canvas frame with `.thinMaterial`, which is a blur. The image was to remain untouched with an indicator over it; instead the whole canvas is blurred. Violates AC90.2, which requires the canvas to keep showing what it was showing.
- **The curtain divider does not track the pointer.** `ComparisonView.swift:245` divides `value.location.x`, which is local to the 28-point drag handle, by `window.contentView.frame.width`, which is the whole window including the filter side panel, with a `?? 600` fallback. Two coordinate errors compounding. Violates AC90.5 and the divider behaviour AC67.2 carries over.

Slice 10 was added by a `CONFIRM DELIVER` of 2026-08-23. `make test-gui` becomes a gate for the remaining slices rather than a baseline comparison only once it is clean, and two of the three failures test the pricing and account surface this MVP pauses and slice 9 removes --- so they are superseded behaviour, not violated behaviour. The work is to establish what each was written to satisfy before reverting it, so that nothing is dropped silently.

## Exclusions

Text-to-image generation; user-saved filters; live pricing and account clients; any second model; output-fidelity polish; release hardening, signing and notarisation; filter corpus revision; batch processing; undo and redo.

**Undo and redo are out of scope for the v2 MVP and are expected afterwards** (author's ruling, 2026-08-24). Slice 9c's rendering cache is designed so as not to foreclose them: renderings are keyed by what produced them --- the asset's identity, the model, the sizing and the face setting --- so prior renderings remain valid and addressable rather than being cleared when the working asset moves. What an undo system additionally needs is a history of operations with their inputs, a way to move through it, and a ruling on what undoing an *applied* filter means when that filter cost money and its result is on disk. None of that is built here, and nothing here prevents it.

**Filter wording is not changed by any slice.** 26 of the 86 filters carry no preserve clause, which was recorded as authorial work outstanding. The author's ruling of 2026-08-23 is that this is deliberate: those filters describe a style rather than a transform, and `requiresInput` is where that distinction is recorded. No filter body is edited by this delivery. `IMPLEMENTATION_GUIDE_v2.md` section 8 is corrected accordingly.

## Residual risk

- Slice 3 modifies the tested v1 core. The SSIM quality gate is a required gate on that slice.
- The stitching buffer allocates roughly 36 bytes per output pixel, all resident, which bounds supported output resolution. The documented caps warn above 4096 pixels on the long edge and refuse above 8192.
- Real-provider validation requires human credentials and incurs charges, so it cannot be covered by automated tests.
- **The rendering store of slice 9c holds four renderings.** At 8 megapixels that is roughly 32 MB each as pixels, so about 128 MB resident, alongside the stitching buffer above. Raised by `audit-acs` on #90 and carried into #91 as an input to the memory cap rather than discovered there. The bound is on entry count, not on bytes, which is the cheaper thing to get wrong for a small image and the more expensive one for a large.
- **The 32-megapixel ceiling of #91 covers stitching, not everything resident.** It is derived from `Tiler.stitch`'s 36 bytes per output pixel and does not account for GFPGAN's working set when face enhancement is on, nor for the rendering store above. Raised by `audit-acs` on #91. The figure is a named constant and revisable; it is approximate rather than measured with everything resident.
- **The minimum-resolution message and the ceiling's reduction message could coincide** at an extreme aspect ratio, where a picture is raised to the 1024 floor and its upscale is then reduced to fit the ceiling. Unlikely rather than impossible, and a presentation question rather than a correctness one if it proves reachable in use.

### Recommendation on L2, lint

`swift-format` 6.3.0 ships in the Xcode toolchain at `/Applications/Xcode.app/Contents/Developer/Toolchains/XcodeDefault.xctoolchain/usr/bin/swift-format`, so `SWIFT.md`'s required formatter costs no new dependency.

Recommended sequence, in two steps rather than one:

1. **Now:** a `make lint` target that lints only the files the current issue changed. Value immediately, no whole-tree diff.
2. **After the delivery closes:** one isolated commit adopting `swift-format` across the tree, then chain `test: lint`. That commit touches every file and must not overlap other work.

Adopting the full reformat mid-delivery would put a several-thousand-line whitespace diff in front of the review that accepts nine slices of behaviour. That is the only reason to wait.

### Recommendation on L3, coverage

`llvm-cov` is present in the same toolchain and `swift test --enable-code-coverage` produces the profile. Recommended:

- Add `make coverage`, which reports per-target line coverage. **Report, do not gate.**
- Run it once at delivery close rather than per ticket, since it roughly doubles the pack's runtime and the standing instruction is not to run the pack superfluously.
- Record the number in Verification evidence, so the definition of done has an answer either way.

Gating at 80% now would fail on the SwiftUI views, which the package tests cannot reach because `make test` does not build the app target. That is a measurement artefact rather than a real coverage gap, and gating on it would reward writing tests against the wrong boundary.
