## Original issue body

## Problem

Sketches (pencil drawings, ink drawings, etc.) are being classified as photographs by the content auto-detector, causing the photo model (realesrgan-x4plus) to be selected instead of the anime/illustration model (realesrgan-anime-6b).

The current `ContentDetector` uses Apple's `VNClassifyImageRequest` and checks only the `illustrations` label with a threshold of 0.5. Sketches may not trigger the `illustrations` label — they might score on different labels like `drawing`, `sketch`, `art`, etc.

## Investigation needed

1. Run `VNClassifyImageRequest` on several sketch images to see what labels score highest
2. Determine whether broadening the label set (beyond just `illustrations`) improves detection
3. Determine whether the threshold needs adjustment

## Investigation findings

Ran `VNClassifyImageRequest` on both images:

| Image | Type | `illustrations` score | `art` score |
|-------|------|----------------------|-------------|
| remy2.jpg | Photograph | 0.3057 | 0.3057 |
| sketch1.png | Children's book illustration | 0.1443 | 0.1443 |

**The photo scores higher on `illustrations` than the actual illustration.** VNClassifyImageRequest is a semantic content classifier (playground, children, outdoor, etc.), not a style/medium classifier. It cannot reliably distinguish illustrations from photographs.

Labels like `drawing`, `sketch`, `cartoon`, `anime`, `clipart` do not exist in the taxonomy at all.

### Conclusion

VNClassifyImageRequest is the wrong tool for style detection. We need a different approach.

### Proposed solution: colour analysis heuristic

Illustrations typically have:
- Fewer distinct colours (flat fills, limited palette)
- Larger uniform-colour regions
- Sharper, more defined edges (no camera noise or continuous-tone gradients)

A simple heuristic: **sample the image and count distinct colour clusters.** Illustrations have dramatically fewer than photographs. This could work alongside the existing Vision labels (for cases where the label does fire) or replace them.

Alternative: train a small custom CoreML classifier on illustration vs photo images. More accurate but more work.

**Recommendation:** Start with the colour analysis heuristic — it's simple, fast, and doesn't require training data. Fall back to the anime model when the image looks "illustration-like" by this metric.

### Comment by tigger-developer at 2026-03-19T19:26:27Z

## Updated solution: colour diversity heuristic

VNClassifyImageRequest is unreliable for style detection (see investigation above). Replacing with a **colour diversity heuristic** that measures how many distinct quantized colours appear in the image.

### How it works

1. Sample up to 10,000 pixels evenly across the image
2. Quantize each pixel to 5-bit per channel (32 levels per channel)
3. Count distinct quantized colours
4. Compute ratio: distinct colours / sample count

### Empirical data

| Image | Type | 5-bit distinct | Ratio |
|-------|------|---------------|-------|
| toby.jpg | Photo | 1779 | 0.178 |
| remy2.jpg | Photo | 965 | 0.097 |
| sketch1.png | Illustration | 336 | 0.034 |

Threshold of **0.065** cleanly separates: illustrations below, photos above. ~1.9× margin on both sides.

### Combined approach

Keep VNClassifyImageRequest as a secondary signal (in case it catches something the colour heuristic misses), but add colour diversity as the primary illustration detector:

1. Compute colour diversity ratio
2. If ratio < 0.065 → illustration
3. Else if VNClassifyImageRequest `illustrations` >= 0.5 → illustration
4. Else → photo

### Risk

Only tested on 3 images. Threshold may need tuning for edge cases (B&W photos, highly detailed illustrations). But this is already far more reliable than VNClassifyImageRequest alone.

## Implementation

Replaced VNClassifyImageRequest (unreliable for style detection) with a **colour diversity heuristic** as the primary classifier:

1. Sample up to 10,000 pixels evenly across the image
2. Quantize each pixel to 6 bits per channel (64 levels)
3. Count distinct quantized colours
4. If ratio (distinct / samples) < 0.28 → illustration

Vision labels kept as secondary signal (only trusted at ≥ 0.5 confidence).
