## Solution Design

### Scope

- Import the initial bundled prompt set from `/Users/tigger/snips/prompts-genai/image/*.md` into app resources under the repository.
- Preserve prompt bodies while adding or deriving stable IDs, display names, and categories.
- Default prompt-pack compatibility to the MVP FAL model unless a resource specifies narrower compatibility.
- Defer user-authored prompt-pack editing until after MVP v2.0.

### Patterns to follow

- Treat prompt packs as data resources, not hard-coded switch statements.
- Use structured metadata where needed and format-aware parsing for structured files.
- Keep prompt composition in `SuperscaleUXCore` so it can be tested without launching SwiftUI.

### Anti-patterns to avoid

- Do not make prompt copy final for MVP; placeholder/internal names are acceptable.
- Do not bake prompt text into SwiftUI views.
- Do not require network access to load or test bundled prompt packs.
- Avoid CODING.md violations: regex/line-editor parsing of structured metadata, duplicated hard-coded prompt lists, and hidden validation errors.
- Avoid CODE/SWIFT.md violations: force unwraps when loading resources and empty `catch` blocks around bundle access.

### Test locations

- `Tests/SuperscaleUXCoreTests/` for prompt-pack loading, validation, and composition tests.
- App resource tests if the Xcode project requires a separate resource-bundle check.

## Dependencies

- Depends on v2 module boundaries.
- Blocks polished Generate mode prompt-pack selection.
