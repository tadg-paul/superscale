## Original issue body

## Parent

Sub-issue of #14 (Phase 8: macOS SwiftUI GUI).

## Problem

The GUI app is currently built as an SPM executable target. This causes:

1. **No proper `.app` bundle** — requires a hand-rolled bundle with symlinked models, manual Info.plist, and an AppDelegate hack for activation. macOS doesn't treat it as a real app (no Dock icon, no menu bar until forced).
2. **Brittle build/launch cycle** — binary path changes after `swift package clean`, `--target` builds don't link the executable, stale caches prevent code changes from taking effect.
3. **No SwiftUI previews** — the standard SwiftUI development workflow is unavailable without Xcode.
4. **No asset catalogue** — app icon, accent colour, and other resources can't be managed properly.
5. **No entitlements or code signing** — required for App Store distribution (#15) and sandboxing.

## Solution

1. Create `SuperscaleApp/SuperscaleApp.xcodeproj` with a macOS app target
2. Add the existing Swift package as a local package dependency so the Xcode project imports `SuperscaleKit`
3. Move GUI source files into the Xcode project's source group
4. Add asset catalogue, entitlements, auto-generated Info.plist
5. `make gui` builds via `xcodebuild` and symlinks models into the app bundle
6. Remove `SuperscaleApp` executable target from `Package.swift`
7. Remove old `Sources/SuperscaleApp/` directory
