## Original issue body

## Problem

In the GUI's custom resolution mode, there is no upper limit on the values a user can type. It is easy to accidentally enter extremely large numbers (e.g. cursor in wrong position, stale digits), which would attempt to allocate enormous buffers and exhaust memory.

## Solution

Cap custom dimension values at the smaller of 8× the longest input dimension or 16384px. The cap is applied as the user types — values exceeding the limit are truncated to the maximum.

When an image is loaded with custom dimensions already set, the dimensions are re-evaluated against the new 8× limit and capped if they exceed it (e.g. user types 16000 with no image, drops a 300×300 image → cap becomes 2400, value is reduced).

When a value is capped, the info panel displays a warning explaining the limit.

Partially implemented in [\`dbde6e9\`](https://github.com/tigger04/superscale/commit/dbde6e9) and [\`4924527\`](https://github.com/tigger04/superscale/commit/4924527).
