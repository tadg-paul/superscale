## Original issue body

## Problem

Superscale needs CoreML `.mlpackage` model files at runtime. The default model (RealESRGAN_x4plus) is approximately 65 MB as a `.pth` file; CoreML conversion may produce a similar or larger `.mlpackage`. With six models, total storage is roughly 200–400 MB.

We need to decide where models live and how they reach the user. This decision affects Phases 5 (Distribution) and 6 (Model download).

## Options

### Option A: Bundle all models in the Homebrew bottle

Models are compiled into the release archive. `brew install` delivers everything.

**Pros:**
- Zero-config — works immediately after install
- No network required at runtime
- Simple implementation

**Cons:**
- Large download (~300–400 MB bottle)
- Users get models they may never use
- Homebrew bottles have a soft size expectation (~50 MB); this is well above

### Option B: Bundle default model, download others on demand

The default model (RealESRGAN_x4plus, ~65 MB) ships with the binary. Other models are downloaded on first use.

**Pros:**
- Reasonable install size (~65–80 MB)
- Works immediately for the most common use case
- Other models available via `superscale -m anime input.png` (auto-download) or `superscale --download-models` (pre-fetch)

**Cons:**
- Requires network for non-default models
- Download infrastructure to build and maintain
- SHA256 verification needed

### Option C: Download all models on first use

No models bundled. First run triggers a download.

**Pros:**
- Tiny install size (just the binary, ~5 MB)
- Clean separation of binary and data

**Cons:**
- Broken out of the box — first run requires internet
- Bad UX: `brew install superscale && superscale photo.png` fails without network
- Requires download infrastructure from day one

### Option D: Git LFS in the repository

Models stored via Git LFS, pulled on clone or build.

**Pros:**
- Models versioned alongside code
- Reproducible builds

**Cons:**
- Git LFS has bandwidth quotas on GitHub (1 GB/month free)
- Does not help with Homebrew distribution
- Complicates the build for contributors

## Recommendation

**Option B: bundle default model, download others on demand.**

This balances UX (works immediately for the primary use case) with download size (stays within Homebrew norms). It defers the download infrastructure to Phase 6 (Model download) while Phase 5 (Distribution) only needs to ship one model.

The model storage location should be:
- **Bundled model:** installed to the Cellar with the binary, symlinked or discovered via the binary's path
- **Downloaded models:** `~/Library/Application Support/superscale/models/` (macOS convention, also compatible with future App Store sandboxing)

Note: `~/.local/share/superscale/models/` follows XDG convention but conflicts with macOS App Store sandbox expectations. Using `~/Library/Application Support/` keeps the door open for Phases 9–11 (App Store).
