## Original issue body

## Problem

`CoreMLInference.swift` calls `MLModel.compileModel(at:)` on every invocation. This compiles the `.mlpackage` source format into a device-optimized `.mlmodelc` in a temporary directory — then discards it when the process exits. For all 7 models (6 Real-ESRGAN + GFPGAN), this adds ~4 seconds of startup overhead on every run, even though the compiled output is identical each time on the same hardware.

For the CLI this is a noticeable delay. For the future GUI app (Phase 8), a 4-second spinner on every launch would be unacceptable.

## Context

Raised by [@m13v](https://github.com/m13v) in [#4 comment](https://github.com/tigger04/superscale/issues/4#issuecomment-2752327795), based on experience with WhisperKit's CoreML integration. The `.mlmodelc` cannot be pre-compiled and distributed because compilation is device-specific (optimized for the user's exact Neural Engine/GPU). It must be compiled once per device and cached.

## Solution

Cache the compiled `.mlmodelc` to a persistent, known path. On subsequent runs, check for the cached version and load it directly with `MLModel(contentsOf:)`, skipping compilation.

### Cache location

`~/Library/Application Support/superscale/compiled/` — this directory is already the convention used by `ModelRegistry` for user model storage, and is accessible under App Sandbox for the future GUI phases.

### Cache key

The cache must be invalidated when the source model changes (e.g. after a version upgrade that ships updated `.mlpackage` files). Use the `.mlpackage` directory's modification date as the cache key. Store the key alongside the `.mlmodelc` and recompile if it doesn't match.

### Changes required

1. **`ModelCache.swift`** (new) — Cache management: compile-or-load strategy, cache key validation, cache clearing.

2. **`CoreMLInference.swift`** — Replace direct `MLModel.compileModel(at:)` with `ModelCache.loadCompiledModel(at:)`.

3. **`SuperscaleCommand.swift`** — Add `--clear-cache` flag.

### What this does NOT change

- Model discovery and resolution (ModelRegistry)
- Tiling, pipeline, or image I/O
- Model download or distribution format (still `.mlpackage`)
