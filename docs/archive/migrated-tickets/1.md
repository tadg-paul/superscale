## Original issue body

## Problem

GFPGAN is a dedicated face enhancement model that significantly improves upscaled faces (eyes, teeth, skin texture). Real-ESRGAN's Python CLI offers this via `--face_enhance`. Superscale currently excludes it entirely.

## Why it's not bundled

GFPGAN's pretrained weights embed components with non-commercial licences:

- **StyleGAN2** (NVIDIA): non-commercial use only
- **DFDNet**: CC BY-NC-SA 4.0 (non-commercial, share-alike)

GFPGAN's Apache-2.0 licence explicitly carves these out. Bundling the weights would constrain Superscale's own licence and create confusion about what downstream users can legally do.

Note: the licence restrictions apply to **the model weights**, not to images produced by the model. Users can use face-enhanced images commercially.

## Solution

Support GFPGAN as an **optional user-initiated download** that, once installed, runs automatically.

### Behaviour

1. **Download is explicit**: `superscale --download-face-model` with licence notice and confirmation
2. **Once downloaded, face enhancement is automatic**: whenever faces are detected in an upscaled image, they are enhanced — no flag needed
3. **Opt-out available**: `--no-face-enhance` skips face enhancement even when the model is present
4. **Without the model**: face enhancement is silently skipped (no error — user simply hasn't opted in)

### Pipeline ordering

Face enhancement runs **after** upscaling. This is the same order used by the upstream [Real-ESRGAN `--face_enhance` flag](https://github.com/xinntao/Real-ESRGAN):

```
Input → Tile → Upscale (Real-ESRGAN) → Stitch → Face Enhance (GFPGAN) → Output
```

**Rationale:** GFPGAN works best on faces at reasonable resolution (~512×512 face crops). Running it on the upscaled output gives it a much larger face region with more detail to refine than the original low-res input.

### Face detection

Use Apple's built-in [VNDetectFaceRectanglesRequest](https://developer.apple.com/documentation/vision/vndetectfacerectanglesrequest) (available since macOS 10.15) to detect face regions in the upscaled image. This keeps face detection native and fast, and only the enhancement model itself needs to be downloaded.

The face enhancement pass:

1. Detect face bounding boxes in the upscaled image using `VNDetectFaceRectanglesRequest`
2. For each detected face, crop with padding (1.5× the bounding box, matching upstream)
3. Run the cropped face through the GFPGAN CoreML model
4. Blend the enhanced face back into the upscaled image (feathered edges to avoid seams)

### Model download

1. `superscale --download-face-model` fetches the pre-converted CoreML model from our GitHub release
2. Display a clear licence notice before download: the model is for non-commercial use only due to StyleGAN2/DFDNet components
3. Require explicit user confirmation (interactive prompt or `--accept-licence` flag)
4. Store the downloaded model in `~/Library/Application Support/superscale/models/`
5. The GFPGAN weights are never committed to the repo, never included in Homebrew formula, never redistributed by us

### CLI usage

```bash
# Download the face model (one-time, with licence prompt)
superscale --download-face-model

# From now on, faces are automatically enhanced during upscaling
superscale portrait.png

# Skip face enhancement for this run
superscale --no-face-enhance portrait.png
```

   - `--accept-licence` flag: non-interactive licence acceptance

4. **`scripts/convert_gfpgan.py`** — Conversion script for GFPGANv1.4.pth → CoreML. Uses `gfpganv1_clean_arch` (no CUDA extensions), wraps for tracing with post-processing.

5. **Tests**:
   - RT-041: `--face-enhance` without model → exit 1, stderr contains "download"
   - RT-042: .gitignore, formula, tracked files all exclude GFPGAN

Research confirms conversion is feasible:

- Noise generation must be externalized (handled in our wrapper)
- The `_clean_arch` variant works with standard PyTorch ops
