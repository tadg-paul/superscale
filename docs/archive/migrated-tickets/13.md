## Original issue body

## Problem

Only the default model (RealESRGAN_x4plus) is bundled with the Homebrew install. Users who want other models (anime, general compact, x2plus) need a way to get them. Currently there is no mechanism for this.

## Solution

Per owner direction: all models are small enough (~111MB total) to bundle with the install. The approach is twofold:

### 1. Bundle all models in Homebrew formula

Update the Homebrew formula to download and install **all six models** as resources, not just the default. Total download: ~111MB (compressed zips, store-only).

| Model | Zip size |
|-------|----------|
| RealESRGAN_x4plus | 33MB |
| RealESRGAN_x2plus | 33MB |
| RealESRNet_x4plus | 33MB |
| RealESRGAN_x4plus_anime_6B | 8.7MB |
| realesr-animevideov3 | 1.2MB |
| realesr-general-x4v3 | 2.4MB |

The formula already has the infrastructure for model resources — it just needs all six instead of one. All models install to \`<prefix>/models/\` in the Cellar, which ModelRegistry already searches.

### 2. CLI download for non-Homebrew installs

For users who build from source or install manually, add a \`--download-models\` CLI command that:

1. Reads \`models/manifest.json\` (bundled with the source) for URLs and SHA256 hashes
2. Downloads each missing model from the GitHub release (\`models-v1\`)
3. Verifies SHA256 after download
4. Extracts to \`~/Library/Application Support/superscale/models/\`
5. Shows progress: bytes downloaded, percentage, model name

### 3. Auto-download on first use (interactive only)

When a user runs \`superscale -m anime input.png\` and the anime model is missing:

- **Interactive (TTY):** prompt to download (see also issue #20 for the interactive prompt UX)
- **Non-interactive:** exit with error and instructions

### Download implementation

Use \`URLSession\` for downloads — it's built into Foundation, supports progress reporting, and handles HTTPS. Verify SHA256 using \`CommonCrypto\` or \`CryptoKit\` (both available on macOS 14+).

### Manifest

The manifest (\`models/manifest.json\`) already exists with URLs and SHA256 hashes for all six models. The \`ModelDownloader\` reads this at runtime to know what to fetch and how to verify it.
