## Original issue body

## Problem

Large images cannot be processed in a single CoreML inference pass due to memory constraints. The image must be split into tiles, each tile upscaled independently, then the results stitched back together. Tiles must overlap to avoid visible seams at tile boundaries.

## Solution

Implement a `Tiler` component in `Sources/Superscale/Pipeline/`:

### Split

- Given an image and a tile size, produce a grid of overlapping tiles
- Overlap size is a fixed proportion of tile size (e.g. 32px for 512px tiles)
- Edge tiles may be smaller than the configured size
- Return tile images along with their position metadata (origin, overlap region)

### Stitch

- Given a set of upscaled tiles with position metadata, reassemble into the full output image
- Blend overlap regions using linear interpolation to avoid hard seams
- Output dimensions = input dimensions × scale factor

### Configuration

- Default tile size determined by model (from ModelRegistry)
- Overridable via `--tile-size` CLI flag
- Smaller tiles use less memory but more passes (slower)
