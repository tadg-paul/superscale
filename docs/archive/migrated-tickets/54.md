## Original issue body

## Parent

Sub-issue of #14 (Phase 8: macOS SwiftUI GUI). Related to #48 (app icon and distribution).

## Problem

The current \`make release\` target distributes the CLI only via a Homebrew formula. The GUI app has no distribution mechanism. Users who want the GUI must build from source.

## Solution

Add a \`make release-gui\` Makefile target that builds the GUI app, packages it as a DMG, and distributes via a Homebrew Cask in the existing tap (\`tigger04/homebrew-tap\`).

### Makefile targets (clarified scope)

- \`make release\` — CLI only. Tags, builds CLI binary, updates Homebrew **formula** (\`superscale.rb\`). Unchanged.
- \`make release-gui\` — GUI only. Builds \`.app\` bundle via \`xcodebuild\`, packages as DMG, uploads to GitHub release, updates Homebrew **cask**.

### Shared models (no duplication)

Models are not bundled inside the \`.app\`. Instead, both CLI and GUI share a single model location:

1. **\`~/Library/Application Support/superscale/models/\`** is the shared model directory. \`ModelRegistry.searchPaths\` already includes this path — no SuperscaleKit code changes needed.
2. **Homebrew Cask \`postflight\`** copies models to Application Support if they aren't already there (e.g. from a prior CLI install).
3. **If CLI is already installed via Homebrew**, the GUI finds models via the Cellar search path — no copy, no duplication.
4. **If only the GUI is installed**, models are placed in Application Support by the cask postflight.

This avoids duplicating 112MB of models between CLI and GUI installs. App Store distribution (Phase 9, #15) will need its own approach due to sandboxing — that is a separate concern.

### Steps for \`make release-gui\`

1. Run \`make test\` and \`make test-ssim\` (unless \`SKIP_TESTS=1\`)
2. Build release \`.app\` bundle via \`xcodebuild -configuration Release\`
3. Code sign (ad-hoc initially; Developer ID for notarization later)
4. Package as DMG (\`hdiutil\`)
5. Upload DMG to GitHub release
6. Update Homebrew cask in tap with new version and SHA256

### Open questions

- **Cask name:** \`superscale-gui\` to distinguish from the CLI formula \`superscale\`? Or use the same name with Homebrew resolving formula vs cask by install method?
