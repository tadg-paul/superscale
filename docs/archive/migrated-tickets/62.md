## Original issue body

## Problem

When upscaling `icon3.png` (a transparent PNG from test images) and toggling face enhancement, the cached version without face enhancement has a black background instead of preserving transparency. The face enhancement toggle swaps to this incorrect cached version.

## Steps to reproduce

1. Drop `Tests/images/icon3.png` on the GUI
2. Upscale (with face enhancement enabled)
3. Toggle face enhancement off
4. The displayed image has a black background where transparency should be

## Root cause hypothesis

The `onPreFaceEnhance` callback captures the stitched CGImage before face enhancement AND before alpha channel recombination (step 6 in Pipeline). The cached "without faces" image is missing its alpha channel, so transparent regions render as black.

## Solution

Move the `onPreFaceEnhance` callback to fire after alpha recombination but before face enhancement. The callback should capture the fully composited image (with alpha) minus only the face enhancement step.

### Comment by tigger-developer at 2026-04-01T14:15:44Z

## Implementation

**Root cause confirmed:** `onPreFaceEnhance` fired at pipeline step 5, before alpha recombination at step 6. The `stitched` image at that point has all-opaque alpha values (inference strips transparency), so the cached pre-face image had no transparency.

**Fix in `Pipeline.process`** (commit 0425ba1):
- Alpha channel is now upscaled at step 5 (before the callback), rather than step 6
- The callback receives `recombineAlpha(stitched, upscaledAlpha)` — fully composited with correct transparency
- Face enhancement continues to operate on the RGB-only `stitched` image (FaceEnhancer uses `noneSkipLast` internally, so this is correct)
- Step 6 reuses the already-upscaled alpha to recombine into the final output — no duplicate upscaling
