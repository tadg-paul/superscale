## Original issue body

## Problem

Superscale UX v2 needs FAL image generation support in Swift. Existing behaviour in `../pix` and provider patterns in `../storyboard-gen` should be ported as a GUI-only service, not re-invented in SwiftUI views and not exposed through the `superscale` CLI.

The MVP v2.0 provider scope is FAL only. Future Google and Replicate support should follow the provider lessons from `../storyboard-gen`, but it is not part of the MVP implementation.

## Solution Design

### Scope

- Implement FAL generation services in `FalGenerationKit`.
- Port request semantics from `../pix`: `https://fal.run/{endpoint}`, `Authorization: Key <generation-key>`, image URL parsing, and first-image download.
- Add a data-driven FAL model registry with `xai/grok-imagine-image` as the default MVP model.
- Add handler strategies for text-to-image and image-to-image/edit quirks.
- Support up to three reference images.
- Keep Google and Replicate as post-MVP architecture notes only, informed by `../storyboard-gen`.

### Patterns to follow

- Use Foundation networking abstractions that can be tested with local fixtures or `URLProtocol`.
- Keep request construction outside SwiftUI views.
- Keep model-family quirks in handlers rather than conditionals spread across the app.
- Redact secrets centrally before diagnostics reach UI or logs.

### Anti-patterns to avoid

- Do not call paid FAL endpoints from automated tests.
- Do not add Google or Replicate provider UI in the MVP issue.
- Do not make the CLI depend on generation services.
- Avoid CODING.md violations: stringly typed structured-data parsing where Codable or typed models are appropriate, silent error suppression, and source-grep tests.
- Avoid CODE/SWIFT.md violations: `try!`, force unwraps, empty `catch`, and hidden networking inside SwiftUI views.

### Test locations

- `Tests/FalGenerationKitTests/` for request construction, response parsing, registry, handlers, diagnostics, and fixture HTTP tests.
- Test fixtures under `Tests/FalGenerationKitTests/Fixtures/` or the project-equivalent test resource path.
