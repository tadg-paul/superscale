## Original issue body

## Problem

After `make install`, running `superscale` from any directory fails with:

```
Error: Model not found: realesrgan-x4plus. Run 'make convert-models' or download via --download-models.
```

The models exist locally at `<project>/models/` but the binary cannot find them.

### Root cause

`make install` symlinks `~/.local/bin/superscale` → `<project>/.build/release/superscale`. When the binary resolves this symlink, `Bundle.main.executableURL.resolvingSymlinksInPath()` gives `<project>/.build/release/superscale`. The "alongside executable" search path then looks for `<project>/.build/release/models/` — which does not exist. The models are at `<project>/models/`, two directories up.

### Search paths checked

1. `<project>/.build/release/models/` — does not exist
2. `<project>/.build/models/` — does not exist (Cellar layout path)
3. `~/Library/Application Support/superscale/models/` — does not exist
4. `<cwd>/models/` — only works if run from the project root

None of these find `<project>/models/`.

## Solution (implemented)

Added a symlink step to the `make install` target:

```makefile
@ln -sfn "$(CURDIR)/models" "$(CURDIR)/$(BUILD_DIR)/models"
```

This creates `.build/release/models/` → `<project>/models/`, so the existing "alongside executable" search path finds the models.
