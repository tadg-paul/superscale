## Original issue body

## Problem

Superscale UX v2 needs a lightweight history surface so generated and upscaled outputs can be recovered, reviewed, retried, and audited. The MVP storage decision is plain files plus JSON metadata, not a database.

## Test Enumeration And Type Justification

`RT-77.1` through `RT-77.7` are regression tests because history persistence, redaction, filtering, and actions are ongoing app behaviours.

`UT-77.1` is a user test because usefulness versus overreach is a product judgement.

## Solution Design

### Scope

- Add app-managed storage for generated and upscaled assets.
- Store session metadata as JSON next to or near asset files.
- Add History mode based on `docs/v2/WIREFRAMES.md`.
- Support generated, upscaled, failed, and cancelled session records where safe diagnostics exist.
- Provide reopen, send-to-Upscale, save, and reveal actions.

### Patterns to follow

- Use Codable models for JSON metadata.
- Keep file layout documented in code comments or docs if it is not obvious.
- Keep storage services testable with temporary directories.
- Redact secrets before metadata is persisted.

### Anti-patterns to avoid

- Do not introduce a database for MVP v2 history.
- Do not persist API keys, account data, or unredacted authorization headers.
- Do not turn History into a full digital asset manager in this issue.
- Avoid CODING.md violations: line-oriented JSON handling, hidden filesystem errors, and hardcoded paths.
- Avoid CODE/SWIFT.md violations: force unwraps, empty `catch`, and unstructured background UI updates.

### Test locations

- `Tests/SuperscaleUXCoreTests/` for session store, metadata, redaction, and temporary-directory storage tests.
- GUI/app test target for History mode state and actions.

## Dependencies

- Depends on v2 foundation, Generate workspace, and upscale handoff.
