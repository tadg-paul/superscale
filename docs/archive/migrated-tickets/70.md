## Original issue body

## Problem

Superscale UX v2 needs generation features without turning the existing `superscale` CLI into a second image-generation product. The repository needs explicit GUI-only module boundaries and a mode-based app shell so later FAL, prompt-pack, history, and settings work can land without creating dependency drift.

The Phase 0 planning decisions are recorded in `docs/v2/VISION.md`, `docs/v2/ARCHITECTURE.md`, `docs/v2/WIREFRAMES.md`, and `docs/v2/IMPLEMENTATION_PLAN.md`. This issue creates the implementation foundation for those decisions.

## Solution Design

### Scope

Implement the foundation for v2 GUI work only:

- add `FalGenerationKit` and `SuperscaleUXCore` boundaries, preferably as Swift package targets;
- keep `Superscale` CLI depending only on the existing local-upscale layer;
- add a mode-based SwiftUI app shell with Upscale, Generate, History, and Settings navigation;
- leave Generate, History, and Settings modes as skeletal surfaces unless needed for this issue's tests.

### Patterns to follow

- Follow `docs/v2/ARCHITECTURE.md` for module boundaries and dependency direction.
- Follow `docs/v2/WIREFRAMES.md` for the first-pass app shell shape.
- Keep SwiftUI views declarative; put state and side effects in view models or services.
- Use Swift structured concurrency only when asynchronous work is introduced.

### Anti-patterns to avoid

- Do not add generation commands, flags, or help text to the CLI.
- Do not put networking, persistence, or Keychain logic inside SwiftUI `body` implementations.
- Do not introduce a multi-provider abstraction in this foundation ticket.
- Do not reorganize unrelated Xcode project structure.
- Avoid CODING.md violations: clever compact code over clarity, source-code string grep tests, and hidden errors from broad/empty catches.
- Avoid CODE/SWIFT.md violations: force unwraps, `try!`, empty `catch`, and background updates to UI state.

### Test locations

- `Tests/SuperscaleTests/` for package and CLI-boundary regression tests if the existing suite is the project standard.
- New target-specific tests under `Tests/FalGenerationKitTests/` and `Tests/SuperscaleUXCoreTests/` if Swift package targets are added.
- GUI mode-state tests in the app test target or existing GUI test harness, depending on current project support.
