## Original issue body

## Problem

After v2 generation, settings, prompt packs, and history are implemented, the GUI release path needs hardening so bundled resources are packaged, secrets are excluded, CLI and GUI artefacts remain distinct, and MVP manual smoke tests cover the paid/provider paths that automated tests intentionally avoid.

## Test Enumeration And Type Justification

`RT-78.1`, `RT-78.2`, and `RT-78.3` are regression tests because resource packaging, CLI scope, and release wording are ongoing release behaviours.

`OT-78.1` and `OT-78.2` are one-off tests because they inspect a specific release candidate or dry-run artefact.

`UT-78.1` through `UT-78.5` are user tests because paid provider smoke checks and release wording review require human judgement and real credentials.

## Solution Design

### Scope

- Update GUI packaging to include prompt packs and v2 resources.
- Ensure local session history, generated images, API keys, and account data are never bundled.
- Confirm CLI and GUI release paths remain separated.
- Add release checklist coverage for real FAL smoke tests outside automated regression.
- Document post-MVP provider direction without shipping Google or Replicate support in MVP v2.0.

### Patterns to follow

- Keep automated tests fixture-backed and credential-free.
- Use release-candidate inspection for one-off artefact checks.
- Keep release wording aligned with `docs/v2/VISION.md` and `docs/v2/IMPLEMENTATION_PLAN.md`.

### Anti-patterns to avoid

- Do not add paid FAL calls to `make test`.
- Do not package secrets, local account data, or generated session artefacts.
- Do not imply Google or Replicate support ships in MVP v2.0.
- Avoid CODING.md violations: hidden release-script errors, hardcoded credentials, and build-system recursion in regression tests.
- Avoid CODE/SWIFT.md violations where release hardening touches app code: empty catches, force unwraps, and UI state changes from background work.

### Test locations

- Existing release or licensing/package tests for resource presence and CLI scope.
- One-off tests under the project's one-off test convention if artefact inspection is automated.
- Manual UT checklist documented on this issue for paid FAL and wording review.

## Dependencies

- Depends on the core v2 feature issues being implemented.
- Should run after Generate, Settings, Prompt Packs, Pricing/Account, and History are available.
