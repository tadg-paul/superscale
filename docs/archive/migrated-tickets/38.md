## Original issue body

## Problem

Currently `--scale` only accepts integer values (2 or 4), matching the fixed model scale factors. Users who want an image at a specific resolution (e.g. making a 512×512 image into 4096×4096) must upscale with Superscale and then separately resize with another tool. This is a common workflow for old photos, avatars, and assets.

Additionally, there is no way to request a fractional scale (e.g. 2.4×).

## Solution

### New switches

| Switch | Type | Description |
|--------|------|-------------|
| `--width` | `Int` | Target width in pixels |
| `--height` | `Int` | Target height in pixels |
| `--stretch` | `Flag` | Ignore aspect ratio when both `--width` and `--height` are specified |

### Changed switch

| Switch | Change |
|--------|--------|
| `--scale` | `Int` → `Double`. Accepts any positive value (e.g. `2.4`, `6.0`, `3`). |

### Behaviour

1. **`--scale` (float):** Upscale using the best available model, then resize to the exact target scale using `CGContext` with `.high` interpolation quality (Lanczos under the hood — already proven in the codebase for alpha and face resize).

2. **`--width` only:** Scale proportionally so output width matches target. Height scales to preserve aspect ratio.

3. **`--height` only:** Scale proportionally so output height matches target. Width scales to preserve aspect ratio.

4. **`--width` and `--height` together (default):** Fit within the bounding box preserving aspect ratio. E.g. a 100×200 image with `--width 2000 --height 2000` → 1000×2000.

5. **`--width` and `--height` with `--stretch`:** Resize to exact dimensions, ignoring aspect ratio.

6. **Mutual exclusion:** `--scale` and `--width`/`--height` in the same command → validation error.

7. **`--stretch` without both `--width` and `--height`** → validation error.

### Warning for beyond-native-scale targets

When the effective target scale exceeds the model's native scale factor (e.g. requesting 6× from a 4× model), emit a warning to stderr:

```
Warning: Target scale 6.0× exceeds model's native 4× — standard interpolation will be used for the remaining 1.5×. Some pixellation may be visible.
```

The upscale still proceeds — the value proposition is that AI upscaling to 4× + interpolation for the rest is still better than pure interpolation from the start.

### Pipeline changes

The resize step happens **after** the full pipeline (upscale, stitch, face enhance, alpha) and **before** writing output. This keeps the pipeline clean — all AI processing happens at native model resolution, and the final resize is a simple post-processing step.

### Apple APIs

`CGContext` with `interpolationQuality = .high` — already used in `FaceEnhancer.resize()` and `Pipeline.upscaleAlpha()`. Consistent with existing codebase, no new dependencies needed.

### Changes required

1. **`SuperscaleCommand.swift`** — Add `--width`, `--height`, `--stretch` options. Change `--scale` from `Int` to `Double`. Add validation (mutual exclusion, stretch requires both dimensions). Calculate effective target resolution and pass to pipeline.
2. **`Pipeline.swift`** — Accept optional target dimensions. After the stitch/enhance/alpha steps, resize to target if specified. Emit warning when target exceeds native scale.
3. **`ImageWriter.swift`** — `outputFilename()` currently uses model scale for the suffix; update to reflect actual output dimensions or effective scale.
4. **README.md** — Document new switches with examples.
5. **docs/architecture.md** — Add resize step to pipeline diagram.

## Implementation

Commit: f8ecc29

### Changes

**`SuperscaleCommand.swift`**
- Changed `--scale` from `Int` (default 4) to `Double?` (optional)
- Added `--width: Int?`, `--height: Int?`, `--stretch: Bool` options
- Added validation: mutual exclusion of `--scale` and `--width`/`--height`, `--stretch` requires both dimensions, `--scale` must be positive
- `modelScale` (2 or 4) computed from `--scale` value for auto-detection; `filenameScale` computed from resolved model's actual scale

**`Pipeline.swift`**
- `process()` signature expanded with `requestedScale`, `targetWidth`, `targetHeight`, `stretch`
- Added `resolveTargetDimensions()` — handles all cases (explicit scale, width-only, height-only, both, stretch, default native)
- Added `resizeImage()` — uses `CGContext` with `.high` interpolation quality (Lanczos)
- Post-pipeline resize step after stitch/face-enhance/alpha, before write
- Warning emitted when effective target scale exceeds model native scale

**`ImageWriter.swift`**
- `outputFilename(for:scale:)` changed from `Int` to `Double`
- Formats integer scales as `4x`, fractional as `2.4x`

**`README.md`** — Added usage examples for fractional scale, width/height, stretch, and wdn model
**`docs/architecture.md`** — Added resize step to data flow diagram and new "Target resolution" section

### Testing

8 regression tests (RT-071 through RT-078) all passing. Full regression suite: 65 tests, 0 failures.

```bash
# Fractional scale
superscale -s 2.4 photo.png

# Width only (proportional)

superscale --width 1920 --height 1080 --stretch photo.png
```
