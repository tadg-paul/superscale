## Original issue body

## Problem

Running `superscale --help` in an interactive terminal hangs indefinitely with no text displayed. The pager process never receives or displays the help text.

**User environment:**
- `MANPAGER=less`
- `PAGER=less`
- `LESS="-RiF"`

When stdout is piped (non-interactive), `--help` works fine — the bug only manifests when the pager code path is triggered.

## Root cause

Swift's `Process` (NSTask) API does not properly connect child processes to the controlling terminal. Every approach using `Process` hangs for interactive pagers like `less`. `popen`/`pclose` and `Darwin.system()` are both marked `__swift_unavailable`. A C shim (`CSystemShim`) was created to expose C `system()`.

### Current state (after commit 192078d)

The pager hang is fixed (launches via `c_system()`), and help text is now static (two string constants in `HelpText.swift`). However, two issues persist:

1. **No colours** — `HelpText.coloured` uses only bold (`\033[1m`) and underline (`\033[4m`) ANSI codes. No actual colour codes are present. The user requires a proper colour scheme for headings, options, and syntax elements.
2. **Pager launches when piped** — `superscale --help | cat` still invokes the pager. The shell script's `[ -t 1 ]` check inside `c_system()` does not reliably detect piped stdout.

## Solution

**Make help text static and handle everything in a shell script.**

The dynamic model listing and conditional GFPGAN licence in `HelpFormatter` added complexity for no real benefit — `--list-models` already shows installation status. By making the help text static, we eliminate runtime generation and can handle the entire help flow in a simple shell script.

### Static help text

- **MODELS section** lists all eight models (seven default-install plus GFPGAN) with descriptions but **no installation status**. `--list-models` covers that.
- **LICENCE section** always mentions GFPGAN licence (relevant info regardless of installation state).
- **Both coloured and plain versions** are string constants — no `HelpFormatter.format()` call at runtime.

### Shell script handles everything

Swift writes both versions to temp files. A shell script (via `c_system()`) does the rest:

```sh
coloured='/tmp/superscale-help-c-PID'
plain='/tmp/superscale-help-p-PID'

if [ -t 1 ] && [ -t 0 ] && [ -z "${NO_COLOR+x}" ]; then
    # Interactive terminal, no NO_COLOR → pager with coloured text
    pager="${MANPAGER:-${PAGER:-less}}"
    case "$pager" in
        less|*/less|"less "*)
            pager="$pager -R"
            ;;
    esac
    $pager "$coloured"
else
    # Piped or NO_COLOR → plain text to stdout
    cat "$plain"
fi
rm -f "$coloured" "$plain"
```

### Colour rules

1. **Always show colours** — unless `NO_COLOR` is set.
2. **Never show colours in piped (non-pager) output.**
