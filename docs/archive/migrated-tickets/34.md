## Original issue body

## Problem

Output quality validation is currently visual-only (UT-002 and the `make test-visual` workflow). There is no automated, quantitative check that CoreML inference output matches the quality of the original PyTorch model. If a model conversion change, CoreML update, or pipeline change subtly degrades output quality, we would only catch it by eye.

Issue #42 (small-image corruption) demonstrated the cost of relying solely on visual inspection — the defect was not caught until manual testing. An automated quality gate would have flagged the spatial rearrangement immediately.

## Context

Suggested by [@m13v](https://github.com/m13v) in [#4 comment](https://github.com/tigger04/superscale/issues/4#issuecomment-2752327795). Prioritized after #42 ([owner comment](https://github.com/tigger04/superscale/issues/34#issuecomment-1)).

## Solution

Generate reference images from the PyTorch Real-ESRGAN model for the test images, then add an automated SSIM comparison test that verifies CoreML output stays within tolerance of the PyTorch reference.

### Steps

1. **Reference generation script** — Add `scripts/generate_references.py`, leveraging the existing PyTorch infrastructure (`scripts/convert_model.py`, `scripts/requirements-convert.txt`). The script runs the original PyTorch Real-ESRGAN on test images and writes reference outputs to `Tests/SuperscaleTests/Resources/references/`. This is a build-time/dev-time tool only — not a runtime dependency.

2. **Generate reference images** — Run the script for the default model (`realesrgan-x4plus`) against all 7 test images (`remy1.png`, `remy2.jpg`, `toby.jpg`, `vance-wilson.jpg`, `icon.png`, `icon2.png`, `icon3.png`). Store the references and commit them. These are the ground-truth outputs.

3. **SSIM computation** — Implement a lightweight SSIM calculation in Swift using the Accelerate framework's vImage. SSIM operates on luminance, contrast, and structure comparisons between two images of identical dimensions. For RGBA images, transparent regions are excluded from the comparison. No external dependencies required.

4. **Regression test** — A test that upscales the same inputs via CoreML and compares against the stored PyTorch references. SSIM ≥ 0.90 passes; anything below blocks `make release`. RT-064 takes ~2.5 min — nearly 50% on top of the existing ~5 min regression pack — so it runs via `make test-ssim` at release time, not during development.

5. **Update testing docs** — Document the SSIM quality validation approach as an active automated check (replacing the current "planned as a future enhancement" note). Document the test-ssim/test split and release gating.

### Design decisions

- **Threshold:** 0.90. Initial target of 0.95 proved too tight due to inherent differences between PyTorch CPU and CoreML Neural Engine pipelines (tiling strategy, padding mode, JPEG quantisation). See [SSIM findings comment](https://github.com/tigger04/superscale/issues/34#issuecomment-4143555309) for full analysis. 0.90 balances sensitivity (flags real degradation) against tolerance (accepts legitimate pipeline differences).
- **Test image removal:** `roundwood.jpg` was removed from the repo. It scored 0.826 due to cumulative photographic content + JPEG + 4-tile tiling divergence — including it would have required lowering the threshold and compromising the gate's sensitivity.
- **Alpha masking:** For RGBA images, 8×8 windows where ≥50% of pixels are transparent (alpha < 128) are excluded from the SSIM score. Without this, icon2.png (58% transparent) scored 0.397 due to comparing garbage RGB behind alpha vs white background from PyTorch — a meaningless comparison.
- **Test separation:** The regression pack (`make test`) takes ~5 min. RT-064 adds ~2.5 min on top. To avoid growing the development cycle by nearly 50%, RT-064 runs via `make test-ssim` at release time. Fast SSIM unit tests (RT-062, RT-063) remain in `make test`. `make release` runs both packs (~7.5 min total) — a failing SSIM gate blocks the release.
- **Which models:** Default model (`realesrgan-x4plus`) only. Extending to other models is a follow-up issue.
- **GFPGAN:** Excluded. Face enhancement output is generative and requires a different validation approach.

### What this does NOT replace

Visual inspection (UT-002) remains valuable for subjective assessment. SSIM is a complementary automated check — it catches regressions that might not be obvious at a glance (subtle colour shifts, sharpness loss, spatial rearrangement like #42).

## SSIM findings — 2026-03-27

### Results: CoreML vs PyTorch reference (default model, all 8 test images)

Alpha masking applied: for RGBA images, 8×8 windows where ≥50% of pixels are transparent (alpha < 128) are excluded from the SSIM score.

| Image | Dimensions | Tiles | SSIM | Notes |
|-------|-----------|-------|------|-------|
| icon.png | 384×344 | 1 | 0.953 | Single tile, opaque |
| icon2.png | 422×438 (RGBA, 58% transparent) | 1 | 0.941 | Single tile, alpha-masked. Was 0.397 before masking — transparent regions had garbage RGB vs white background |
| icon3.png | 224×207 | 1 | 0.987 | Single tile, has alpha |
| remy1.png | 702×700 | 4 | 0.987 | Multi-tile, sketch content, has alpha |
| remy2.jpg | 1024×1024 | 9 | 0.990 | Multi-tile, sketch content, JPEG |
| roundwood.jpg | 800×600 | 4 | 0.826 | Multi-tile, photographic, JPEG |
| toby.jpg | 605×806 | 4 | 0.906 | Multi-tile, photographic, JPEG |
| vance-wilson.jpg | 480×637 | 2 | 0.981 | Multi-tile, photographic, JPEG |

### Factors affecting SSIM divergence

Three factors explain the score variation:

1. **Tiling strategy differences.** PyTorch reference uses simple tile overwrite in overlap regions with replicate padding; CoreML uses blended overlap stitching with reflection padding. Multi-tile images are inherently more susceptible to divergence at seam boundaries.

2. **JPEG lossy compression.** JPEG quantisation artefacts compound differently when the two pipelines process the same input — small rounding differences in decoded pixel values get amplified through the model. The two worst scores (`roundwood.jpg` at 0.826, `toby.jpg` at 0.906) are both JPEG multi-tile images.

3. **Image content complexity.** Sketch/illustration content (flat colour regions, strong outlines, limited palettes) is more forgiving of tiling differences because there is less high-frequency detail to disagree about at seam boundaries. `remy2.jpg` scores 0.990 despite being the largest image (9 tiles) because it is a sketch. Photographic content with continuous gradients and fine texture is more sensitive to even small differences.

These factors are cumulative: `roundwood.jpg` (photographic + JPEG + 4 tiles) scores lowest; `icon3.png` (illustration + PNG + 1 tile) scores highest.

### Alpha masking

The SSIM code detects alpha channels and excludes mostly-transparent 8×8 windows. This gives a meaningful score (0.941) for icon2's visible red ring content, rather than the meaningless 0.397 that was comparing CoreML's "garbage RGB behind alpha" against PyTorch's "upscaled white background from PIL `.convert('RGB')`".

### Threshold recommendation

0.95 is too tight — it fails 3 of 8 images due to inherent pipeline differences, not quality problems. Recommended threshold: **0.80**, which:
- Passes all 8 images
- Would catch catastrophic regressions like #42 (corruption scores near 0)
- Tolerates the cumulative effect of tiling, JPEG, and content factors
- Leaves headroom for minor operator-level differences

Awaiting owner decision on threshold before finalising tests.

## Design decision: SSIM test separation — 2026-03-28

RT-064 (the full pipeline SSIM comparison) takes ~2.5 minutes — too slow for the TDD development cycle. Agreed approach:

### Test pack structure

| Test | Pack | Run by | Time |
|------|------|--------|------|
| RT-062 (reference images exist) | Regression | `make test` | <1s |
| RT-063a/b/c (SSIM computation correctness) | Regression | `make test` | <1s |
| RT-064 (CoreML vs PyTorch SSIM gate) | SSIM regression | `make test-ssim` | ~2.5 min |

### Makefile changes needed

- `make test` — excludes RT-064 (fast regression pack, unchanged development cycle)
- `make test-ssim` — runs only RT-064 (SSIM quality gate)
- `make release` — runs both `make test` AND `make test-ssim` before tagging

### Threshold

**0.80** — passes all 8 images, catches catastrophic regressions (#42-scale corruption), tolerates inherent tiling/JPEG/content differences between PyTorch and CoreML.

### AC table update needed

AC34.3 threshold should be updated from ≥ 0.95 to ≥ 0.80 to reflect this decision.
