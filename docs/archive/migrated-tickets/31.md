## Original issue body

## Problem

`brew install tigger04/tap/superscale` fails with:

```
Errno::ENOENT: No such file or directory - RealESRGAN_x4plus.mlpackage
```

This is a sub-issue of #12 (Homebrew distribution).

## Root Cause

The model zips (created by `scripts/release-models.sh`) each contain a single top-level directory:

```
RealESRGAN_x4plus.mlpackage/
  Manifest.json
  Data/
    com.apple.CoreML/
      weights/weight.bin
      model.mlmodel
```

Homebrew's `UnpackStrategy` strips a single top-level directory when staging resources. So inside the `resource().stage` block, the working directory contains the *contents* of `.mlpackage` (`Manifest.json`, `Data/`, etc.) — not the `.mlpackage` directory itself.

The formula then calls:

```ruby
(prefix/"models").install "#{model}.mlpackage"
```

This looks for `RealESRGAN_x4plus.mlpackage` in the staging directory, but it doesn't exist — its contents are there instead. Hence `Errno::ENOENT`.

## Solution

Change the formula's resource staging to install the staging directory contents *as* the `.mlpackage` directory:

```ruby
resource(model).stage do
  (prefix/"models"/"#{model}.mlpackage").install Dir["*"]
end
```

This takes all files in the staging directory (the stripped contents of the `.mlpackage`) and installs them into `prefix/models/RealESRGAN_x4plus.mlpackage/`.

The fix must also be reflected in `scripts/release.sh` which generates the formula dynamically on each release.
