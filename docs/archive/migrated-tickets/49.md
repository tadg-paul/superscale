## Original issue body

## Parent

Sub-issue of #44 (Phase 8b — GUI app scaffold and core upscaling).

## Problem

The GUI currently shows a static scale indicator. The CLI supports flexible scale and resolution options (`--scale`, `--width`, `--height`, `--stretch`) but these are not exposed in the GUI. Users need to control output resolution without dropping to the command line.

## Solution

Replace the scale indicator with a full scale/resolution picker that mirrors the CLI's capabilities.

### Preset scales

Buttons offering: **2×, 4×, 8×, Custom**. Each preset button shows the target resolution in parentheses (e.g. "4× (2048×2048)" for a 512×512 input). Default selection is the model's native scale.

### Custom resolution

Selecting "Custom" reveals two text fields (width × height). Both fields are editable, but the **last-clicked** field is the defining dimension:

- Clicking into the **width** field and typing a value makes width the defining dimension. The height field auto-populates with the aspect-ratio-preserving value, shown **dimmed** to indicate it is indicative only. Only `--width` equivalent is passed to the pipeline.
- Clicking into the **height** field and typing a value makes height the defining dimension. The width field auto-populates dimmed. Only `--height` equivalent is passed.
- The indicative (dimmed) dimension updates live as the user types in the defining field.

### Stretch mode

A "Stretch" checkbox, visible only in custom resolution mode:

- When checked, **both** fields are fully editable, **neither is dimmed**, and both values are passed to the pipeline with the `stretch: true` flag
- This allows non-aspect-ratio output (e.g. 1920×1080 from a 4:3 source)

### Integration

All scale/resolution options use the existing `Pipeline.process(requestedScale:targetWidth:targetHeight:stretch:)` API — no changes to SuperscaleKit needed.
