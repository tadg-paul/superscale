## Original issue body

## Parent

Sub-issue of #14 (Phase 8: macOS SwiftUI GUI).

## Problem

All pipeline and model management code currently lives in the `Superscale` executable target. The planned GUI app needs to share this code. A library target must be extracted before any GUI work can begin.

## Solution

1. Create a `SuperscaleKit` library target in `Package.swift`
2. Move all pipeline components into the library: `Pipeline`, `ImageLoader`, `ImageWriter`, `Tiler`, `CoreMLInference`, `ContentDetector`, `FaceEnhancer`, `FaceDetector`, `ModelRegistry`, `FaceModelRegistry`, `ModelCache`, `SSIM`
3. The `superscale` CLI executable becomes a thin wrapper: argument parsing + orchestration, importing `SuperscaleKit`
4. `CSystemShim`, `HelpText`, `Pager`, and `SuperscaleCommand` stay in the CLI target (CLI-specific)
5. All existing regression tests must pass with no functional changes

This is a pure refactor — no new features, no behaviour changes.
