## Original issue body

## Problem

When upscaling a small image (e.g. a 256×256 icon) that fits within a single tile, the output has faded/black edges. The visible effect is that the image appears "sized larger than target resolution and cropped" — the centre content looks correct but the edges are progressively faded to black, making the useful content area appear zoomed-in.

Reported by user running `superscale icon.png` with no extra arguments.

## Root cause

`Tiler.blendWeight()` (`Sources/Superscale/Tiler.swift:176-191`) applies distance-based edge fade-out to **all** tile edges unconditionally. This is correct for overlap zones between adjacent tiles (smooth blending), but incorrect for tile edges that sit at the image boundary with no neighbouring tile.

For a single-tile image (e.g. 256×256 input, tileSize=512):
- The entire image is one tile
- `blendWeight()` fades all four edges from weight=0 at the border to weight=1.0 at `overlap` pixels inward
- After normalization (`colorAccum / weightAccum`), pixels near edges with very small weights become noisy or black
- Pixels at exact edges (weight=0) become black (`weightAccum[i] == 0` → `outputPixels[i] = 0`)

The same bug affects edge tiles in multi-tile images — any tile edge that is flush with the image boundary should not fade, only edges where an adjacent tile overlaps.

## Solution

Modify `blendWeight()` to accept flags indicating which edges of a tile are actual overlap zones (have adjacent tiles). Edges at the image boundary get weight=1.0 instead of fading.

### Changes

**`Tiler.swift`**

1. Add an edge-adjacency struct or flags parameter to `blendWeight()`:

```swift
private static func blendWeight(
    x: Int, y: Int, width: Int, height: Int, overlap: Int,
    fadeLeft: Bool, fadeRight: Bool, fadeTop: Bool, fadeBottom: Bool
) -> Float {
    guard overlap > 0 else { return 1.0 }
    let o = Float(overlap)
    let left = fadeLeft ? min(Float(x) / o, 1.0) : 1.0
    let right = fadeRight ? min(Float(width - 1 - x) / o, 1.0) : 1.0
    let top = fadeTop ? min(Float(y) / o, 1.0) : 1.0
    let bottom = fadeBottom ? min(Float(height - 1 - y) / o, 1.0) : 1.0
    return min(left, right, top, bottom)
}
```

2. In `stitch()`, before blending, determine which edges of each tile have adjacent tiles. A tile edge should only fade if there is another tile overlapping that edge:

- `fadeLeft = (tile.origin.x > 0)` — there's content to the left
- `fadeRight = (tile.origin.x + tileWidth < outputWidth)` — there's content to the right
- `fadeTop = (tile.origin.y > 0)` — there's content above
- `fadeBottom = (tile.origin.y + tileHeight < outputHeight)` — there's content below

For a single-tile image covering the full output, all flags are `false` → weight=1.0 everywhere → no fading.
