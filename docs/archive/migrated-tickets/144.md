## Problem statement

**Observed by the author, second raising:**

> *"cmd+c to copy the image, cmd+v to paste (2nd time raising this)"*
> *"> cmd should only allow paste on blank canvas"*

## The guard is the requirement

He wrote the constraint as a nested quote under the request, and gave the reason the first time he
raised it:

> *"but only on the blank canvas, otherwise if we hit it by mistake, the existing image will be lost"*

**So a paste that replaces a working picture is the defect being pre-empted, not an edge case.**
Cmd+V is a key pair people hit by muscle memory, and the cost of getting it wrong is the loss of a
lock chain that has been paid for at a provider. This is closely related to #143, and deliberately
solved by *refusal* rather than by a warning: a paste onto a working canvas is almost certainly a
mistake, and the cheapest correct answer to a mistake is for nothing to happen.

## What copy means

**Copy the picture the canvas is currently showing** --- which is the base, the candidate or the
upscaled rendering depending on what is displayed. The graph already answers "what is displayed"
(`WorkspaceState.displayedAsset`), so this reads from the model rather than from a view, which is
the rule #103 established for the upscale allocation and for the same reason.

Guide **2.2** promises paste as one of three import routes and it has never existed. This closes
that half too.

## Violated criteria

- Guide **2.2**: *"Accepts PNG, JPEG, TIFF and HEIC via drag and drop, the open panel, or paste."*
  Paste has never been implemented; the guide has promised it since v2 was specified.
- Nothing covers copying at all. Expect two new criteria.

## Debugging and fix procedure

1. **Copy writes the displayed asset's bytes to the pasteboard**, asking the graph what is displayed
   rather than reaching for `viewModel.result`. #112 is the ticket about binding to `result` alone
   and losing the case where the scale is off.
2. **Paste is refused unless the canvas is blank**, where blank means the drop target is showing ---
   the same condition #135's clear returns to. Refused silently, or with the menu item simply
   disabled, so there is nothing to dismiss.
3. **Paste accepts the same types drag and drop does**, so the two routes cannot drift apart in what
   they will take. `DropTargetView` already names them.
4. A pasted image enters through the same path as an import, so the graph starts a new chain by
   AC89.8 and nothing special-cases it.

## Test plan

- RT-CLIP.1: with a picture displayed, Cmd+C puts an image on the pasteboard
- RT-CLIP.2: what is copied is what the canvas is showing, not always the base
- RT-CLIP.3: with a blank canvas and an image on the pasteboard, Cmd+V loads it
- RT-CLIP.4: **with a picture already loaded, Cmd+V does nothing and the picture is untouched**
- RT-CLIP.5: the paste command is disabled rather than silently inert when a picture is loaded
- RT-CLIP.6: a pasted picture starts a new chain, as an import does
- RT-CLIP.7: Cmd+C with a blank canvas is unavailable
- UT-CLIP.1: copy a filtered result into another application, and judge it is the picture that was on screen

*Identifiers are placeholders until this issue has its number.*


## Acceptance criteria

- **AC144.1** With a picture on the canvas, the picture the canvas is showing can be copied to the pasteboard.
- **AC144.2** What is copied is what is displayed --- the base when the base is being shown, the derivation otherwise.
- **AC144.3** With a blank canvas, an image on the pasteboard can be pasted in and becomes the source.
- **AC144.4** With a picture already loaded, pasting is unavailable and the loaded picture is untouched.
- **AC144.5** A pasted picture enters the pipeline as an import does, starting a new chain.
- **AC144.6** Copying is unavailable with a blank canvas.

### What this issue delivers, in plain language

The picture on the canvas can be copied out with Cmd+C, and a picture can be brought in with Cmd+V
--- **but only onto an empty canvas**, so a mistyped paste cannot destroy work paid for at a provider.

### Evidence

- The author, twice, with the constraint attached: *"cmd should only allow paste on blank canvas"*,
  and the reason from the first raising: *"otherwise if we hit it by mistake, the existing image will
  be lost."*
- Guide **2.2**: *"Accepts PNG, JPEG, TIFF and HEIC via drag and drop, the open panel, or paste."*
  Paste has been promised since v2 was specified and has never existed.
- `MainView.displayedImage` --- the base when `showsBase`, the derivation otherwise. This is what
  AC144.2 means by "what is displayed".
- **#112** is the precedent for AC144.2: binding to `viewModel.result` alone offered no comparison
  when the scale was off, which is exactly the state a user filtering an undersized picture is in.

### Edge cases

- **Empty pasteboard, or a pasteboard holding text.** `NSImage(pasteboard:)` returns nil and nothing
  happens. Not a criterion --- there is nothing to state beyond "nothing happens".
- **Paste while a picture is loaded.** AC144.4, and the substance of the request.
- **Copy with the base being shown rather than the derivation.** AC144.2 exists precisely for this.
- **Copy with the scale off**, so there is no `result`. Covered by AC144.2's phrasing.
- **A pasted picture below the filterable minimum.** It enters as an import, so #96's raise applies
  unchanged. AC144.5 is what guarantees that rather than a special case.

### Quality self-audit

Six criteria, each a system state. **AC144.4 and AC144.6 are the two negative ones** and both are
load-bearing: the first is the whole point of the ticket, and the second stops a copy command that
offers itself with nothing to copy.

Totals: **0 missing ACs, 0 edge-case gaps, 0 quality violations.**

### Findings

None. One implementation note recorded rather than raised: the guard against pasting onto a loaded
canvas is in **two** places --- the menu item is disabled, and `pastePicture()` refuses anyway. The
command travels through a counter and could in principle be delivered late, and the author's reason
for wanting the guard is that Cmd+V gets hit by accident. The defensive half is the point.
