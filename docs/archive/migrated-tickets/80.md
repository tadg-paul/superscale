## Original issue body

Child of delivery master #79 (slice 0). Lands in its own commit before any other delivery work.

## Problem

`make test` executes one-off tests. The `test` target runs `swift test --skip SSIM_RT064`, which selects every test in the package except one named regression test. One-off tests are therefore included. `OT78_1` (`test_guiReleaseInspectorRejectsSessionAndSensitiveArtefacts`, `Tests/SuperscaleTests/ReleasePackagingTests.swift:39`) was observed executing inside a `make test` run.

`TESTING.md` requires the regression command to reference regression tests only, and requires the separation to hold by location rather than by exclusion.

The current separation is by name filter: `test-one-off` selects `--filter "OT"`, while `test` excludes nothing. Both commands address the same package. Correcting this by adding `--skip "OT"` to the regression command would preserve the defect in a different form: an exclusion list is maintained by hand, and a one-off test whose name does not match the pattern rejoins the regression pack silently.

The two failure modes are not equal. A missing inclusion means regression tests do not run, which announces itself as a smaller test count. A missing exclusion means a one-off test runs inside the regression pack unnoticed. The mechanism must fail the first way.

## Solution

One-off tests move to a **separate Swift package** in a separate directory, taking a local path dependency on the main package. The regression command addresses the main package and cannot resolve the one-off package's tests at all. No filter, no skip list, nothing to maintain.

Separate *targets* within the existing package would be insufficient: SwiftPM builds and runs every test target in a package by default, so the regression command would still require a filter naming the regression targets. That is an inclusion list, safer than an exclusion list but still a list.

### Layout

```text
Package.swift                 main package
Sources/
Tests/
  SuperscaleTests/            regression
  FalGenerationKitTests/      regression
  SuperscaleUXCoreTests/      regression
OneOff/
  Package.swift               one-off package, path dependency on ".."
  Tests/OneOffTests/          relocated one-off tests
```

### Entry points

| Target | Command | Scope |
|---|---|---|
| `make test` | `swift test --skip SSIM_RT064` | main package only |
| `make test-one-off` | `swift test --package-path OneOff` | one-off package only |
| `make test-one-off ISSUE=n` | `swift test --package-path OneOff --filter "OT.*n"` | one issue's one-off tests |

An `ISSUE=` value matching no one-off test reports the absence rather than passing silently. A vacuous pass would let a developer believe an issue's one-off tests ran when none exist.

`--skip SSIM_RT064` remains on the regression command and is unrelated to this change: it excludes a slow *regression* test, which `make test-ssim` runs separately. That is a duration trade-off inside regression, not a category boundary.

### Relocation

`OT78_1` is the only test carrying a one-off identifier. It moves to the one-off package. Its sibling `RT-78.1` exercises the same release-inspector script and remains in regression; only the one-off test moves.

**The moved test's path computation must be adjusted.** `ReleasePackagingTests` derives the repository root by walking a fixed number of parent directories up from `#filePath`. A file relocated into a package at a different depth breaks that relationship. The moved test must resolve the repository root correctly from its new location; a fixed parent count that happened to be right in the old location is not carried over unchanged.

**Its fixture location must be corrected at the same time.** `ReleasePackagingTests.swift:12-13` writes fixtures to `projectRoot/.agent/tmp/release-packaging-tests` — project-local scratch inside a runtime-state directory. `TESTING.md` requires mutable test state in a unique per-run directory beneath the operating-system temporary directory. The fault predates this issue, but the file is being moved here and `TESTING.md`'s migrate-on-touch rule applies. The fixture root moves to a `mktemp`-allocated directory; the existing teardown already removes it, so only the location changes.

### Detecting a misplaced one-off test

Structure prevents one-off-package tests from reaching regression. It cannot prevent a developer adding a one-off-identified test to a main-package target, so that case halts the regression command instead of passing unnoticed.

**The guard lives in the regression command itself.** Before the tests start, `make test` enumerates the main package's tests through the build system and stops if any name bears a one-off identifier. It reads the build system's enumerated output rather than source text, so it does not introspect source code.

**The guard is a separately invocable unit that accepts a package path.** It is not inline Makefile logic. That distinction carries real weight:

- It can be exercised against a **synthetic package built in a `mktemp -d` directory**, so its tests never mutate the real packages. Creating fixture test files inside the project would be project-local scratch, which `TESTING.md` prohibits.
- Because exercising it needs no build, its tests are **regression tests rather than one-off tests**. The guard protects behaviour that must hold for the life of the project; as one-off tests it would be verified once and never again.

`make test` therefore invokes the guard against the main package, and RT-80.1 to RT-80.3 invoke the same guard against synthetic fixtures. OT-80.10 confirms the regression command honours the guard's verdict.

**The identifier pattern is precise, to avoid false positives.** `TESTING.md` defines one-off identifiers as `OT-{issue}.{n}`, encoded as a test-name suffix where the framework offers no native marker, producing names of the form `test_something_OT78_1`. The guard matches a case-sensitive `OT` followed by an issue number, a separator and a sequence number, anchored at the end of the test name.

Digits are required and the match is anchored so that a name merely containing those letters cannot trigger it. This matters more than it appears: a guard that halts the regression command on a legitimate test is worse than no guard, because it teaches people to route around it.

Placing it there rather than in a git hook is deliberate:

- `make test` already builds the package, so enumeration costs effectively nothing.
- The guard sits in the command whose scope is being protected, which is where the risk materialises.
- It cannot be bypassed without skipping the regression run entirely.
- The project has no hook infrastructure — no `hooks/` directory, no `init` target, nothing installed in `.git/hooks/` — and a global hooks path is configured, so a project hook would need the chaining pattern `GIT.md` requires. Building that infrastructure inside a test-relocation slice would be disproportionate, and running a build on every commit would be a standing cost for a rare fault.

### Patterns and anti-patterns

- Swift, SwiftPM, XCTest, matching existing project convention. No new test architecture.
- Scope is proven with `swift test --list-tests`, which enumerates without executing. This keeps verification fast and avoids one test command driving another.
- `TESTING.md` forbids a regression test that invokes `make` or the build harness, because regression tests run inside `make test` and would recurse. All verification here is therefore one-off.
- `CODING.md` forbids sed, awk and perl for file modification; relocation uses `git mv` and direct editing.
- `GIT.md` requires the relocation to preserve history, so files move with `git mv` rather than delete-and-create.

### Condition enumeration

- **AC80.1** implies two conditions: no one-off-package test is present in regression, and relocation did not remove the co-located regression test. Covered by OT-80.1 and OT-80.2.
- **AC80.2** implies four conditions: the tests are addressable by the one-off command, they still pass in their new home, an issue filter matching nothing behaves predictably, and an issue filter matching something selects it. Covered by OT-80.3, OT-80.4, OT-80.9 and OT-80.11.
- **AC80.3** implies two conditions: a new one-off test is excluded from regression, and it is included in one-off. Covered by OT-80.5 and OT-80.6, against a synthetic fixture rather than the real packages. The claim is structural — it concerns how the layout behaves for *any* future one-off test — so it demonstrates identically on a synthetic pair, and the project's own packages are never mutated to prove it.

### Synthetic fixtures

RT-80.1 to RT-80.3, OT-80.5 and OT-80.6 all exercise their subject against a synthetic package built for the run rather than against the project's own packages. Creating fixture test files inside the real packages would be project-local mutable test state, which `TESTING.md` prohibits.

Every synthetic fixture:

- is created with `mktemp -d`, never in the project tree and never at a shared path;
- is a minimal package — a manifest and one or two trivial test files — so its size is bounded by construction rather than by a limit that has to be enforced;
- is removed by teardown on success, on failure, and on handled interruption. A fixture surviving a failed run is exactly the residue the rule exists to prevent, and a failed run is when it is most likely.
- **AC80.4** implies two conditions: no regression test was lost by identity, and the suite remains green. Covered by OT-80.7 and OT-80.8.
- **AC80.5** implies five conditions: the guard halts on a misplaced one-off test, proceeds on a clean package, proceeds on a near-miss name, the regression command honours a halt verdict, and it honours a proceed verdict. Covered by RT-80.1, RT-80.2, RT-80.3, OT-80.10 and OT-80.12.

### The guard's package path is a Makefile variable

`make test` invokes the guard with a package path supplied by a variable that defaults to the main package. This is not a test contrivance: the guard accepts a package path by design, so the Makefile supplying one is its natural shape.

It also makes the wiring testable without mutating the project. OT-80.10 and OT-80.12 point that variable at synthetic packages — one holding a misplaced one-off test, one clean — and observe whether the regression command halts. Placing a misplaced test in the real main package to provoke a halt would be project-local mutable test state, which `TESTING.md` prohibits.

RT-80.1 to RT-80.3 cover what the guard decides. OT-80.10 and OT-80.12 cover whether the regression command acts on that decision, which is what protects against the call being removed.

`OT-80.7` compares the regression test-name set before and after relocation. The baseline is captured **before any relocation occurs** and recorded as a fixture; a baseline taken afterwards would make the comparison vacuous. This ordering is part of the specification, not an implementation detail.

`OT-80.8` observes the regression command itself rather than an enumeration of the package. Enumeration is a useful structural check but is not the command a developer runs: an edit to the `test` target could reintroduce one-off tests while every enumeration assertion stayed green. At least one assertion has to watch the real entry point.

### Documentation is not covered by an AC

The README's Makefile Targets table documents `make test` and `make test-ssim` and has never documented `make test-one-off`. This issue changes how one-off tests are invoked, so the table is updated as part of the work.

That update is deliberately **not** expressed as an acceptance criterion with tests. Verifying it automatically would mean parsing the README and the Makefile and comparing their text, which is the documentation-grepping pattern `TESTING.md` prohibits. `MAIN.md` places the obligation elsewhere: documentation review is the fourth Gate 2 hard block, an acceptance validation recorded as review evidence, explicitly not something a regression or one-off test may establish by grepping documentation.

The obligation is unchanged in strength. It is discharged through the instrument the standard specifies.

### Why AC80.5 exists

Package separation guarantees that tests *belonging to the one-off package* cannot be reached by the regression command. It does not guarantee that no test *bearing a one-off identifier* runs in regression: a test named `test_thing_OT99_1` added to a main-package test target would execute inside `make test`, reintroducing the original defect at a different point.

AC80.1 covers what the structure delivers. AC80.5 covers the residual human-error case, which structure cannot prevent and which therefore has to be made visible instead.

The detection operates on the test names the build system enumerates, not on source text, so it does not introspect source code. Because it drives the build system it is a one-off test, and because the condition recurs the solution states where the check runs on an ongoing basis.

### Test type justification

Every test here is a one-off. `TESTING.md` states that a test verifying build-harness or entry-point behaviour must be an OT or a UT and must never be an RT, because regression tests execute inside `make test` and would recurse. These tests examine the scope of the test commands themselves, so they meet that condition. They also verify a one-time relocation.

No user test is allocated. Every condition is machine-verifiable, and `TESTING.md` reserves user tests for outcomes requiring human judgement.

## Out of scope

## What was delivered

One-off tests now live in a separate Swift package, `OneOff/`, taking a local path dependency on the main package. `make test` addresses the main package and cannot reach them. There is no filter and no skip list, so a one-off test added later is excluded because of where it lives rather than because someone remembered to exclude it.

A guard invoked by `make test` covers the case structure cannot prevent: a one-off-identified test placed in a main-package target. It reads the build system's enumerated test names rather than source text, matches an anchored identifier requiring digits so a name merely containing the letters cannot fire it, and takes a package path so its wiring is exercised against synthetic packages instead of by mutating the project.

`scripts/run-one-off.sh` exists because `OT-80.9` caught a real defect: `swift test --filter` exits successfully when its pattern matches nothing, so `make test-one-off ISSUE=<typo>` would have reported success having run nothing.

The relocated test's repository-root resolution was corrected for its new depth, and its fixtures moved off project-local `.agent/tmp` into a temporary directory, per `TESTING.md`.

## Findings worth recording

Three defects were found during implementation, all in work written for this issue:

1. **Deadlock, twice.** SwiftPM locks its build directory, and tests were enumerating the very package whose test run was in progress. Fixed by directing those invocations to a scratch directory, shared across the suite so the package builds once rather than once per test.
2. **Vacuous pass.** The empty-filter behaviour above.
3. **Non-deterministic fixtures.** Generated class names derived from `hashValue`, which is seeded per process.

The audits caught two design faults before any code existed: package separation guarantees one-off *package* tests are unreachable but says nothing about a one-off *identified* test misplaced in the main package, which became AC80.5; and an intermediate remediation reintroduced the documentation-grepping anti-pattern, removed in favour of the Gate 2 documentation review.
