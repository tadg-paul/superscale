## Solution Design

### Scope

- Add a Keychain-backed secret store with injectable test storage.
- Keep generation and account/admin credentials separate.
- Add a non-secret settings store for v2 defaults.
- Add Settings mode UI matching the v2 wireframe at first-pass fidelity.
- ~~Add safe `pix` configuration import.~~ Removed from v2 scope; credentials and defaults are entered directly in the GUI.

### Patterns to follow

- Use Keychain for secrets and app preferences for non-secret defaults.
- Keep Settings view logic in view models or services, not in SwiftUI `body`.

### Anti-patterns to avoid

- Do not store API keys in plain UserDefaults, JSON metadata, or logs.
- Do not fall back from account/admin key to generation key.
- Avoid CODING.md violations including hardcoded credentials and hidden errors.
- Avoid CODE/SWIFT.md violations including empty `catch`, force unwraps, and UI state updates off the main actor.

### Test locations

- `Tests/SuperscaleUXCoreTests/` for settings and injectable secret-store tests.
- GUI tests in the app test target for Settings state and controls.

## Dependencies

- Depends on v2 module boundaries.
- Blocks real FAL generation from the GUI and account/pricing display.
