## Original issue body

## Problem

`superscale --download-face-model` has three issues:

1. **Cryptic error on failure**: Uses `Data(contentsOf:)` which gives `"The file couldn't be opened"` on HTTP errors (404, network failure). Users get no indication of what went wrong.
2. **Missing unzip step**: The download URL points to a `.zip` file but the code writes it directly as `.mlpackage` without unzipping. A `.mlpackage` is a directory — writing a zip blob to that path creates a regular file CoreML can't load.
3. **No model available yet**: The GFPGAN CoreML model hasn't been converted and uploaded to the `models-v1` release. This is tracked in #1 — this issue covers the download/install code path only.

## Solution

Fix `handleDownloadFaceModel()` in SuperscaleCommand.swift:

1. Use `URLSession` for the download so we can inspect HTTP status codes and provide clear error messages
2. Download to a temporary `.zip` file, then unzip using `Process("/usr/bin/unzip")`, then move the `.mlpackage` directory to the destination
3. Clean up the temp zip on success or failure
4. Report clear errors: "Download failed (HTTP 404)" or "Network error: ..."
