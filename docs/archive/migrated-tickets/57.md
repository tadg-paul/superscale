## Original issue body

## Parent

Sub-issue of #14 (Phase 8: macOS SwiftUI GUI).

## Problem

All GUI acceptance criteria are manual user tests (UT-NNN). As the GUI grows, manual testing does not scale. XCUITest infrastructure is missing.

## Solution

1. Add a **UI Test target** to the Xcode project
2. Add `.accessibilityIdentifier()` tags to key SwiftUI views (drop target, model picker, scale buttons, compare button, save button, progress indicator, result image, file chooser)
3. Write XCUITests for existing UTs, starting with state checks and working up to interaction tests
4. `make test-gui` Makefile target to run UI tests via `xcodebuild test`
5. Tests involving upscaling use a tiny (8×8) synthetic test image for speed

### Limitations

- NSSavePanel is system-owned and hard to automate — save tests may remain manual (UT)
- CoreML inference needs long timeouts in UI tests
- File chooser (#56) provides an automatable alternative to drag-and-drop

### Comment by m13v at 2026-04-04T08:08:09Z

nice work setting up the XCUITest infrastructure. the .accessibilityIdentifier approach is solid for test automation.

one thing we've found building automated GUI testing for macOS apps: XCUITest's element queries can be flaky when views animate or transition. adding a small helper that waits for an element to become hittable (not just existing) before interacting saved us from a ton of intermittent failures. something like waitForExistence(timeout:) followed by checking isHittable.

for the NSSavePanel limitation, you're right that it's hard to automate directly. one workaround we've used: in debug/test builds, bypass the save panel entirely by accepting a file path via a launch argument or environment variable. the test passes the output path, the app skips the panel and writes directly. keeps the production UX intact while making the flow fully automatable.

the CoreML timeout issue is real. we set our UI test timeouts to 120 seconds for any flow that involves model inference, and added a progress indicator check so the test can distinguish between "still processing" and "hung".
