## Problem statement

**Requested by the author:**

> *"other keyboard shortcuts should apply (2x and 4x superscale toggle, maybe cmd+2 and cmd+4? and face model toggle choose a key binding)"*

**His ruling on the proposal:** *"perfect i accept your recs on those key bindings"* --- namely
**Cmd+2**, **Cmd+4**, **Cmd+8** for the scale toggles and **Cmd+Shift+F** for face enhancement.

## What is being bound

The scale controls are a **toggle group**, not radio buttons: pressing the active choice clears it,
which is how a user turns the scale off and is what `turnScaleOff()` in the GUI suite relies on. So
the shortcuts must **toggle**, matching the buttons exactly:

- **Cmd+2** --- toggle 2x, per his suggestion
- **Cmd+4** --- toggle 4x, per his suggestion
- **Cmd+8** --- toggle 8x, by symmetry. He named 2x and 4x; 8x exists as a third preset and leaving
  it unbound would make the set look arbitrary. **Recorded as an assumption for validation.**
- **Cmd+Shift+F** --- toggle face enhancement. Not Cmd+F, which is Find by universal convention and
  would be the wrong thing to steal in an application with a search field.

## Constraints that shape this

- **Cmd+8 must not collide with anything.** Cmd+1 through Cmd+9 are conventionally view or tab
  switching, and this application has no tabs, so the range is free.
- **The face-enhance shortcut must respect the model's absence.** `faceEnhance` defaults from
  `FaceModelRegistry.isInstalled`, and #93 established that the face controls follow the scale. A
  shortcut that silently sets a flag the interface will not honour is worse than no shortcut.
- **A shortcut that fires while a text field has focus is a defect**, and this application has two
  prominent ones --- the prompt area and the filter search. Cmd-modified keys are safe from ordinary
  typing, which is part of why Cmd+2 rather than a bare digit.

## Violated criteria

- Nothing covers keyboard access to the scale or the face toggle. Expect new criteria.
- **AC82.11**, that no scale is selected at launch, is unchanged and must stay true: a shortcut
  creates a selection where the user asked for one and not otherwise.
- **AC93.3**, that the face controls follow the scale, is unchanged and constrains the face shortcut.

## Acceptance criteria

- **AC147.1** Each scale preset can be put in effect from the keyboard, and pressing the same shortcut again clears it, exactly as pressing its button twice does.
- **AC147.2** A scale shortcut moves the selection rather than adding to it, so at most one preset is ever in effect.
- **AC147.3** Face enhancement can be toggled from the keyboard whenever its control on the canvas would allow it, and cannot when that control would not.
- **AC147.4** Every shortcut is named in a menu, so it can be found without knowing the key.
- **AC147.5** No shortcut fires while the user is typing into a text field.

### What this issue delivers, in plain language

The scale and the face toggle can be driven from the keyboard: **Cmd+2**, **Cmd+4**, **Cmd+8** and
**Cmd+Shift+F**, each behaving exactly as its button does, and each visible in a menu so it can be
discovered rather than memorised.

### Evidence

- The author's request and his acceptance of the proposed bindings.
- `UpscaleViewModel.choose(_:)` --- `scaleSelection.choosing(choice)`, which **toggles**: pressing
  the active choice clears it. The shortcuts call the same method, so they cannot drift from the
  buttons.
- `MainView.faceEnhanceButton` --- disabled on `scaleSelection.isOff`, and routed to a download sheet
  rather than a toggle when `FaceModelRegistry.isInstalled` is false. AC147.3 mirrors both.
- **AC82.11**, no scale selected at launch, is unchanged: a shortcut creates a selection when asked
  and not otherwise.

### Edge cases

- **Cmd+2 twice** --- clears, because the group is a toggle. AC147.1 states it explicitly because the
  obvious implementation is `scaleSelection = .preset(2)`, which would not.
- **Cmd+4 while 2x is in effect** --- moves. AC147.2.
- **Cmd+Shift+F with no scale** --- refused. The canvas button is disabled in that state and the
  shortcut must be too, or the two disagree about the same setting.
- **Cmd+Shift+F with the model absent** --- refused rather than silently setting a flag the interface
  will not honour. The button opens a download sheet instead; the shortcut declining is the more
  conservative of the two and does not surprise.
- **Typing "2" into the prompt or the search field** --- unaffected, because every binding carries
  Cmd. AC147.5 states it anyway, since it is the failure that would make the feature hostile.

against a list of conditions** --- deliberately: the conditions are #93's and may change again, and a
criterion that restates them would then be a second place to keep in step.

Totals: **0 missing ACs, 0 edge-case gaps, 0 quality violations.**
