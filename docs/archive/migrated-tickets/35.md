## Original issue body

## Problem

`superscale --list-models` only lists the 6 Real-ESRGAN upscaling models from `ModelRegistry`. The optional GFPGAN face enhancement model is not shown, even when installed. Users have no way to confirm the face model's installation status from the CLI without trying to use it.

## Current behaviour

```
$ superscale --list-models
Models:
  realesrgan-x4plus        General photo (4×) [default]           [installed]
  realesrgan-x2plus        General photo (2×)                     [installed]
  ...
```

No mention of GFPGAN.

## Expected behaviour

The face model should appear in the list, with its installation status and a note that it's optional/separately licensed:

```
$ superscale --list-models
Models:
  realesrgan-x4plus        General photo (4×) [default]           [installed]
  realesrgan-x2plus        General photo (2×)                     [installed]
  ...

Face enhancement:
  gfpgan-v1.4              Face enhancement (optional)            [installed]
```

If not installed, it should show `[not installed]` with a hint about `--download-face-model`.

## Solution

After the existing `ModelRegistry.models` loop in `SuperscaleCommand.swift` (lines 45–55), add a section that queries `FaceModelRegistry.isInstalled` and prints the face model's status.

The face model should be visually separated from the upscaling models (separate heading or blank line) because it serves a different purpose and has different licensing terms.

### Changes required

1. **`SuperscaleCommand.swift`** — Extend the `--list-models` output block to include `FaceModelRegistry` status after the upscaling models list.

### What this does NOT change

- `FaceModelRegistry` itself (no structural changes needed)
- `ModelRegistry` (face model stays separate by design — different licence terms)
- The `--download-face-model` flow
