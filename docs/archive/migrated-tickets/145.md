## Original issue body

Child of delivery master #139 (the 2026-08-31 user-test round).

## Problem statement

**Observed by the author:**

> *"when i cmd+n i get a new window: I should get a new window with a blank canvas. Either we can handle multiple windows, each with its own stack of lock photos and cached filters, or we disallow new window. in which case cmd+n should clear the image and revert to the drag and droppable initial state."*

**His ruling on the choice:** *"I agree with CMD+N clear the canvas. *if* and only if there are any
unsaved lock images then warn first and allow to cancel."*

## What happens today

Nothing handles Cmd+N. `SuperscaleApp.swift` declares two `CommandGroup(after: .newItem)` blocks ---
Open Image and Open Recent --- but never replaces `.newItem` itself, so **AppKit's default New Window
survives** and a second window opens onto the same single `WorkspaceState` and `UpscaleViewModel`.
Two windows, one model: whatever the second window appears to show, it is the first window's state.

## Why the single-window route, recorded

Multi-window would need a graph, a lock chain, a filter cache and a view model **per window**. Those
are currently one instance each, held at the scene root. That is a structural change to how the
application owns state, not a feature --- and the author chose the other route, which is also the
cheaper and more predictable one.

## What it becomes

Cmd+N **replaces** `.newItem` with a command that clears the canvas back to the drop target, going
through the same path as #135's Clear Image control and #143's warning. It is the same act as the
Clear control, reached by the shortcut a Mac user expects for "start again".

That makes three routes to the same clear --- the control, Cmd+N, and Cmd+O's import --- and **one
implementation behind all three**, which is the point. A warning that fires on some of them is worse
than none.

## Violated criteria

- Nothing covers Cmd+N. Expect a new criterion.
- **AC135.2**, that a clear control is present whenever a picture is loaded, gains a second route and
  is unchanged as a rule.
- **AC135.8** is being amended by #143 and this issue inherits the amended form.

## Test plan

- RT-CMDN.1: Cmd+N with a picture loaded clears the canvas to the drop target
- RT-CMDN.2: Cmd+N does not open a second window
- RT-CMDN.3: with unsaved locked iterations, Cmd+N warns first and cancelling leaves everything intact
- RT-CMDN.4: Cmd+N on an already-blank canvas does nothing and raises nothing
- RT-CMDN.5: after Cmd+N, a picture can be brought in through the drop target
- RT-CMDN.6: the File menu names the command, so it is discoverable without knowing the shortcut
- UT-CMDN.1: press Cmd+N mid-session and judge that it does what starting again should do
