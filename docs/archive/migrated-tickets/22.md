## Original issue body

## Problem

Users must manually specify `-m realesrgan-anime-6b` for anime/illustration content. Most users won't know which model is best for their image. A photo, a manga page, and a digital illustration all benefit from different models, but the default (x4plus) is applied regardless.

## Solution

Add automatic content type detection using Apple's built-in [VNClassifyImageRequest](https://developer.apple.com/documentation/vision/vnclassifyimagerequest) (available since macOS 10.15, well within our macOS 14+ target). This runs a multi-label classification with ~1000 built-in labels in milliseconds, with zero dependencies — the classifier is part of the OS.

### Detection logic

Auto-detection is the **default behaviour** when no `-m` flag is given:

1. Load the input image
2. Run `VNClassifyImageRequest` — returns confidence-scored labels from ~1000 built-in categories
3. Check for anime/illustration indicators among the returned labels (e.g. `drawing`, `cartoon`, `comic_book`, `anime`, `illustration` — exact labels to be confirmed by querying `VNClassifyImageRequest.knownClassifications(forRevision:)` at runtime)
4. If illustration/anime confidence exceeds threshold → select `realesrgan-anime-6b`
5. Otherwise → select `realesrgan-x4plus` (general photo, current default)
6. Scale selection follows independently: if `-s 2` is specified, use the 2× variant of the chosen model

### CLI integration

- Auto-detection is the **default** — no `--auto` flag needed
- `--model` / `-m` always takes precedence as a manual override, bypassing detection entirely
- The detected content type and chosen model are reported in progress output:
  ```
  Detected: illustration → using realesrgan-anime-6b
  ```
  or:
  ```
  Detected: photograph → using realesrgan-x4plus
  ```

### Fallback

If classification confidence is low or ambiguous, fall back to the default model (x4plus), which produces good results on all content types.

### Implementation

1. Add a `ContentDetector` in `Sources/Superscale/ContentDetector.swift`
   - Wraps `VNClassifyImageRequest` 
   - Returns a `ContentType` enum (`.photo`, `.illustration`, `.unknown`)
   - Exposes the confidence score for logging
2. Update `Pipeline` to call `ContentDetector` before model selection when no explicit model was specified
3. Map detected content type + scale to the appropriate model name via `ModelRegistry`

## Notes

- `VNClassifyImageRequest` was introduced at WWDC 2019 (macOS 10.15) — mature and stable
- The classifier runs in milliseconds — negligible overhead compared to inference
- The full label list can be queried at runtime via [`knownClassifications(forRevision:)`](https://developer.apple.com/documentation/vision/vnclassifyimagerequest/knownclassifications(forrevision:))
- We should inspect the available labels to confirm which ones best indicate anime/illustration content before implementation

## Implementation complete

### What was done

1. **`Sources/Superscale/ContentDetector.swift`** — New file wrapping `VNClassifyImageRequest`:
   - `ContentType` enum: `.photo`, `.illustration`
   - `detect(image:)` — runs Vision classification and returns content type + confidence
   - `interpret(labels:)` — separated for testability; applies threshold logic
   - `modelName(for:scale:)` — maps content type + scale to the best CLI model name
   - Illustration threshold set to 0.5 (photos score 0.1–0.35; real illustrations should score 0.6+)

2. **`Sources/Superscale/SuperscaleCommand.swift`** — Updated:
   - `-m` / `--model` is now optional (nil = auto-detect, non-nil = explicit override)
   - When no `-m` given: loads first input image, runs ContentDetector, selects model
   - Reports `Detected: photograph → using realesrgan-x4plus` or `Detected: illustration → using realesrgan-anime-6b`
   - When `-m` given: reports `Using model: <name>` and skips detection

3. **`Tests/SuperscaleTests/ContentDetectorTests.swift`** — 5 tests:
   - RT-035: interpret() with illustration labels above threshold → anime model
   - RT-036: detect() on remy2.jpg (photo) → photo model
   - Plus 3 helper tests for threshold fallback and scale mapping

4. **`Tests/SuperscaleTests/CLITests.swift`** — 2 tests added:
   - RT-037: explicit `-m realesrnet-x4plus` → stderr shows "Using model:", no "Detected:"
   - RT-038: no `-m` flag → stderr shows "Detected:" and model name

### Threshold calibration

VNClassifyImageRequest returns an `illustrations` confidence of 0.25–0.31 for the test photos (remy.png, remy2.jpg). The threshold was set to 0.5 to avoid false positives on photos. Real anime/illustration content should score 0.6+ on this label.
