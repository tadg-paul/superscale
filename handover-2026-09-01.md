## Traps - read before you spend a day on one

### 1. Kill a GUI run and you orphan an application instance

**This cost most of a delivery window.** Five full or partial `make test-gui`
runs were started; several were stopped with `TaskStop`. Each stop left the
launched `Superscale.app` behind. They accumulated to roughly a hundred, and
the suite then failed with:

```
Application 'com.tadgpaul.superscale' does not have a process ID
```

Failures spread into tests the round never touched and the count climbed run
over run - 3 -> 1 -> 35 - which reads exactly like a machine degrading. It was
not. After `pkill`, the same tree ran **223 / 0**.

- **Check with `pgrep -f "Superscale.app/Contents/MacOS"`.**
  `ps -Aco pid,comm | grep Superscale` returns nothing even when a hundred are
  running, because `comm` truncates. That false negative was reported as
  evidence twice.
- **Never run two GUI suites at once.** The second reports
  *"not foreground and does not allow background interaction"*.
- If you stop a run, clean up before starting another.

Four hypotheses were pursued and all four were wrong before the real cause was
found: chip-strip overflow, saved window geometry, an identifier on the
`ScrollView` absorbing hit tests, and `.accessibilityValue` synthesizing a new
element. Each looked plausible, each got a code change, none held. The
abandoned work is in `git stash` as `wip-chip-diagnosis` and can be dropped.

### 2. A GUI run is judged by its `Executed N tests` line and nothing else

A run reported here as "15 failures" had not finished; it completed at **35**.
Counting `Test Case ... failed` lines in a live log is not a result. This rule
is written into #139's own baselines section and was still broken.

### 3. SwiftUI accessibility containers absorb their children

Met three times now:

- The curtain absorbed its divider (#90, D-2)
- The progress badge absorbs its words (#142) - three attempts to make them
  individually addressable all failed; the badge stays `.combine`d and its
  arrangement is asserted through the badge's own height
- An identifier added to the category `ScrollView` made every chip inside it
  unhittable

If a child element cannot be found or clicked, look at what container was
recently identified or declared.

### 4. `CommandGroup(replacing: .pasteboard)` removes the standard Edit menu

It takes Cut, Copy, Paste and Select All away from **every text field in the
application**, including the open panel's "Go to folder" field the suite types
into. Two tests failed with `loadTestImage` timing out at 133 seconds, which
reads as a harness fault. Use `after:`.

### 5. Tests that cannot enter the failing state

**RT-87.37** asserted *"search reaches across categories, so nothing is behind
a chip"* - correctly - and ran from a state with no chip active. The author
reported the defect three times while it stayed green. Widened by #141 to start
from a chipped state.

The same shape appeared in #135's clear tests: they asserted everything the
clear must **do** and nothing it must **not touch**, which is how #140 shipped.

**Eighteen assertions** in the GUI suite used `dropTarget` as proof that the
canvas had cleared. `DropTargetView` is also rendered behind a loaded picture at
`opacity(0.01)` so it can still receive drops, so that identifier is present
either way and every one of those assertions was true before the clear as well
as after. They now wait on the absence of `clearImageButton`, which renders only
when a picture is loaded.

## Where things live

- **`AppCommands`** (in `SuperscaleApp.swift`, not its own file - the target is
  not a synchronized folder). Carries File-menu commands to `MainView`, which
  owns `WorkspaceState` and therefore owns the decision about unsaved work.
  Counters, not booleans, so the same command can be issued twice.
- **`MainView.requestClear()` / `performClear()`** - the split between deciding
  and doing. All three clear routes go through `requestClear`.
- **`viewModel.savedSourceURLs`** - what has been written to disk this session,
  keyed on `inputURL` because that is the displayed source for both save routes.
- **`WorkspaceModel.canGenerateFromNothing` / `generateRequest()`** - the
  prompt-only path. `FalRequestBuilder` already chose the text endpoint when no
  reference was attached; the only gate was `canApply` requiring a working
  image.
- **Test helpers worth knowing:** `waitUntilCanvasIsEmpty()`,
  `clearWarningAlert` (through `app.dialogs`/`app.sheets` - identifiers inside
  a SwiftUI `.alert` do not survive into the `NSAlert`), `compareControl`
  (typed `.any`, because a `Toggle` with `.toggleStyle(.button)` is not an
  `app.buttons`).
